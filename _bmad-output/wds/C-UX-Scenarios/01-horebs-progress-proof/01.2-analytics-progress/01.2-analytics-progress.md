## 3. Mental State (step 12)

**Contexte de la page** : Horeb atterrit sur `/progress` depuis le bloc « progression critique » de Home (01.1), 23 h, thème Nocturne, réseau 3G instable.

| Dimension | Contenu |
|---|---|
| **Trigger** (ce qui la pousse) | Elle vient de lire le bloc « progression critique » qui lui a signalé le gap RDM + 12 révisions dues — elle veut **comprendre pourquoi** sa RDM est le talon d'Achille, pas juste le constater |
| **Hope** | Voir noir sur blanc **l'état, l'évolution et la cause** de son gap RDM dans les 5 questions structurées — pas un score, pas un compteur de tâches (ADR §18.2, trigger-map §7 signal 8) |
| **Worry** | Que le dashboard ne lui donne pas la **cause** du gap (pas juste l'état) — et que le CTA « Réviser » ne l'amène pas vers la bonne surface (`flashcards` pour la file due de 12) |
| **Questions** | « Où suis-je vraiment sur la RDM ? » · « Quelle est la cause de mon stagnation ? » · « Que dois-je faire *maintenant* ? » |
| **Contrainte UX** | Les 5 questions doivent être **actionnables** : le CTA fixe de la surface = « Réviser » (file due) → `flashcards` (01.3). Pas de bouton libre, pas de proposition d'agent — le chemin est le seul chemin (Q8, invariant AD-14) |

## 4. Desired Outcome (step 13)

### Business Goal
**Mesurer la transformation réelle dans le temps (état, évolution, causes, preuves)** — le dashboard `/progress` (ADR §18.6) est le **point de mesure** du flywheel : il alimente le moteur agentique (ADR §18.7) qui détecte la stagnation et déclenche l'analyse de cause (pas un compteur de tâches, ADR §18.2). Source : scenario 01 Q7 (Business Success), strategic-chains Chaîne 01 Q7, ADR §18, trigger-map §5.

### User Goal
**Comprendre l'état + l'évolution + la cause du gap RDM** en lisant les 5 questions structurées — et **l'actionner en 1 geste** vers `flashcards` (01.3) via le CTA fixe « Réviser ». Source : scenario 01 Q4 (Hope), Q8 passo 2, trigger-map §7 signal 8.

## 6. Layout Structure (step 15)

*(PROPOSITION SUGGEST — à confirmer ; NON COUVERT par le corpus gelé pour la disposition interne, dérivé de ADR §18.6 « 5 questions structurées, pas un dashboard de KPIs »)*

**Composition /progress (S-13, ADR §18.6) — 5 questions structurées, pas un dashboard de KPIs :**

```
+-------------------------------------+
| /progress (thème Nocturne, sombre)  |
+-------------------------------------+
| 1. « Où en suis-je ? »             |
|    → État courant : RDM = fragile   |
|    (5/5 dimensions : compre/        |
|     rappel/appl/auton/retention)    |
+-------------------------------------+
| 2. « Comment ça a évolué ? »       |
|    → Tendance : stagnation          |
|    (3 dernières sessions)           |
+-------------------------------------+
| 3. « Pourquoi ? » (causes)         |
|    → 2 causes détectées :           |
|    (a) pas de transfert (recon      |
|       aissance ≠ application)       |
|    (b) 12 révisions dues FSRS       |
+-------------------------------------+
| 4. « Que dois-je faire ? »         |
|    → CTA FIXE : [Réviser]          |
|      (file due 12 cartes RDM)       |
|      → `flashcards` (01.3)          |
+-------------------------------------+
| 5. « Comment je le prouve ? »      |
|    → 4 événements ProgressEvent     |
|    (AD-9) attendus cette session :  |
|    S-19 · S-20 · S-22 · S-38       |
+-------------------------------------+
|  BottomNav (5 tabs, S-31 shared)   |
|  Home · Kanban · Calendar ·        |
|  [Progress] · /agent               |
+-------------------------------------+
```

**Note** : Les 5 questions sont des **sections actionnables** (pas des KPIs) : chaque question a une réponse lisible + une action éventuelle (la question 4 a le CTA fixe). La question 5 liste les 4 événements `ProgressEvidenceCreated` (AD-9) attendus pour cette session (S-19/20/22/38) — c'est le **contract de preuve** du scénario.

## 7. Page States (AD-13, 5 états canoniques)

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default** | Données locales disponibles (PowerSync mirror), gap RDM détecté | 5 questions structurées, CTA « Réviser » actif | Tap sur « Réviser » → `flashcards` (01.3) |
| **Loading** | Charge du dashboard (PowerSync mirror local, AD-7) | Skeleton des 5 questions (~300 ms max, AD-13), CTA indisponible | — |
| **Empty** | Aucune donnée (premier lancement, pas de `UserContext` actif) | État vide actionnable : CTA « Configurer ton profil » → `onboarding` (S-01) ou `mode-coach` (S-21) | Tap sur CTA → onboarding/mode-coach |
| **Error** | Sync hors-ligne + dashboard corrompu | Bandeau « hors-ligne — dernières données locales » (AD-7 : offline = état premier, pas un échec), 5 questions lues en read-only depuis le mirror local | Tap quand réseau revenu |
| **Offline** (AD-7) | Réseau coupé, dashboard chargé depuis le mirror local | Bandeau fine « hors-ligne » (AD-13, A5), CTA « Réviser » reste **actionnable** (les données sont locales, la file FSRS est locale) | Tap sur « Réviser » → `flashcards` (01.3) |
