## 1. Page Purpose (step 10)

**Wording proposé (09/25) :**
> Exécuter le QCM séquentiel généré par l'agent serveur sur le même domaine RDM — le résultat est une `ProgressEvidence` qui **distingue reconnaissance de transfert** (ADR §18.2). À la validation du score, le **CTA fixe « Expliquer pour vérifier »** est le **seul CTA d'action** de la surface, vers `mirror-cognitive` (01.5) — jamais une proposition libre de l'agent (invariant AD-14, Q8 passo 4).

La page ne fait qu'une seule chose : **tester la compréhension par le QCM séquentiel et terminer par le CTA fixe vers le miroir cognitif**.

## 3. Mental State (step 12)

**Contexte de la page** : Horeb atterrit sur `/qcm` depuis le CTA fixe de flashcards (01.3), 23 h, thème Nocturne, réseau 3G instable. Elle vient de terminer la session de 12 cartes RDM.

| Dimension | Contenu |
|---|---|
| **Trigger** (ce qui la pousse) | Elle vient de réviser 12 cartes RDM et veut **vérifier sa compréhension par le QCM** — pas juste cocher des cases, mais distinguer **reconnaissance vs transfert** (ADR §18.2, trigger-map §7 signal 7) |
| **Hope** | Obtenir un score QCM **≥ 80 %** avec la **distinction reconnaissance/transfert affichée** (cible mesurable Q7(a), ADR §18.2) — la preuve qu'elle sait **transférer** la flèche d'une poutre encastrée à un cas réel, pas juste la reconnaître |
| **Worry** | Que le score soit bon (reconnaissance) mais que la **capacité de transfert soit faible** (ADR §18.2, trigger-map §7 signal 7 : « Détecter les cas où un bon score de reconnaissance masque une faible capacité de transfert ») — l'illusion de progression (peur ①, ADR §18.2) ; et que le QCM soit **trop long** (séquentiel, 10-15 questions × 45 s → 8-11 min) et qu'elle abandonne avant le CTA « Expliquer pour vérifier » (fatigue nocturne, ADR §23.1) |
| **Questions** | « Suis-je à la question 3/10 ou 10/10 ? » · « Mon score va-t-il atteindre 80 % ? » · « La distinction reconnaissance/transfert est-elle bien affichée ? » · « Le CTA « Expliquer pour vérifier » est-il bien là à la fin ? » |
| **Contrainte UX** | Le QCM est **séquentiel** (pas de skip) : chaque question a une réponse unique (pas de QCM à choix multiples avec réponses multiples). **À la validation du score** (fin du QCM), le CTA fixe « Expliquer pour vérifier » est le **seul CTA d'action** de la surface (invariant AD-14, Q8 passo 4) — jamais une proposition libre de l'agent. **Le score distingue reconnaissance de transfert** (ADR §18.2) : l'interface affiche les 2 scores séparément (pas un seul score global). Offline = état premier (AD-7) : le QCM est **généré par l'agent serveur** (AD-12, module serveur-only) — si le réseau est coupé, le QCM n'est pas disponible (pas de mirror local pour le QCM, contrairement aux flashcards). |

## 4. Desired Outcome (step 13)

### Business Goal
**Produire 1 `ProgressEvidenceCreated` (AD-9, F-07) qui distingue reconnaissance de transfert** — le QCM produit **≥ 1 preuve vérifiée** (le score QCM avec la distinction ADR §18.2) qui alimente le dashboard Progress (S-13, ADR §18.6). C'est la **2ᵉ preuve de la session** (après les flashcards S-19), dans le contract de 4 preuves (S-19/20/22/38). Source : scenario 01 Q7 (Business Success : 4 `ProgressEvidenceCreated` attendus, 1 par surface de preuve), strategic-chains Chaîne 01 Q7, ADR §18.2/§18.3, F-07.

### User Goal
**Obtenir un score QCM ≥ 80 % avec la distinction reconnaissance/transfert affichée** — le score lui donne la preuve qu'elle **sait transférer** (pas juste reconnaître), et elle est **prête pour le miroir cognitif** (01.5) via le CTA fixe « Expliquer pour vérifier ». Source : scenario 01 Q4 (Hope), Q7(a) (score QCM ≥ 80 % avec distinction), Q8 passo 4, trigger-map §7 signal 7/8.

## 6. Layout Structure (step 15)

*(PROPOSITION SUGGEST — à confirmer ; NON COUVERT par le corpus gelé pour la disposition interne, dérivé de scope-report S-20 + trigger-map §4 Intent #6)*

**Composition QCM (S-20, session séquentielle) — 3 zones fixes (pas un dashboard de widgets) :**

```
+-------------------------------------+
| QCM (thème Nocturne)                |
+-------------------------------------+
|  Zone 1 : Progression              |
|  « Question 3/10 » (badge)         |
|  + timer optionnel                 |
+-------------------------------------+
|  Zone 2 : Question courante         |
|  +-------------------------------- |
|  | [Question RDM]                  |
|  | (ex. « Quel est le moment       |
|  |  fléchissant maximal d'une       |
|  |  poutre encastrée sous charge    |
|  |  uniforme ? »)                   |
|  |                                  |
|  | [Réponse à choix unique]         |
|  |  (4 options, 1 correcte)         |
|  +-------------------------------- |
+-------------------------------------+
|  Zone 3 : Résultat (fin du QCM)    |
|  Score : 8/10 (80 %)              |
|  Reconnaissance : 9/10            |
|  Transfert : 7/10 (⚠️ gap)        |
|  CTA FIXE : [Expliquer pour        |
|   vérifier] → `mirror-cognitive`   |
|  (01.5)                            |
+-------------------------------------+
|  BottomNav (5 tabs, S-31 shared)   |
|  Home · Kanban · Calendar ·        |
|  Progress · /agent                 |
+-------------------------------------+
```

**Note** : Les 3 zones sont fixes (pas de widgets dynamiques, pas de proposition d'agent). La **Zone 1** affiche la progression (Q3/10) + un timer optionnel. La **Zone 2** est la question courante (texte + 4 options à choix unique). La **Zone 3** n'apparaît **qu'à la fin du QCM** : le score global + la **distinction reconnaissance/transfert** (2 scores séparés, ADR §18.2) + le CTA fixe « Expliquer pour vérifier » (seul CTA d'action de la surface, invariant AD-14, Q8 passo 4) — jamais une proposition libre de l'agent.

## 7. Page States (AD-13, 5 états canoniques)

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default** | QCM en cours (question 3/10) | 3 zones : progression (Q3/10), question courante, (Zone 3 masquée jusqu'à fin) | Tap sur option → validation ; tap sur CTA (en fin de QCM) → `mirror-cognitive` (01.5) |
| **Loading** | Génération du QCM par l'agent serveur (AD-12, module serveur-only) | Skeleton des 3 zones (~300 ms max, AD-13), CTA indisponible — **le QCM n'est PAS disponible offline** (AD-7 : offline = état premier, mais le QCM est un module serveur-only) | — |
| **Empty** | QCM non généré (pas de domaine actif) | État vide actionnable : « Aucun QCM disponible » + CTA « Revenir à /progress » (retour natif) | Tap sur CTA → `/progress` (01.2) |
| **Error** | Échec de génération du QCM par l'agent serveur | Message lisible « Erreur de génération du QCM » + CTA « Réessayer » (AD-13, A4 : erreur lisible, retry toujours disponible) | Tap sur « Réessayer » → re-lancer la génération |
| **Offline** (AD-7) | Réseau coupé, QCM non disponible (module serveur-only) | Bandeau fine « hors-ligne — QCM indisponible » (AD-13, A5), actions cloud désactivées **avec explicatif** (pas masquées) | Pas de CTA d'action (le QCM n'est pas actionnable offline) ; retour natif vers /flashcards (01.3) ou /progress (01.2) |
