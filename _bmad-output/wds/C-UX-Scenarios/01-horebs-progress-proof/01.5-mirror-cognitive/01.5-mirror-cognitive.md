## 1. Page Purpose (step 10)

**Wording proposé (09/25) :**
> Horeb explique à voix haute (ou par texte) ce qu'elle a compris de la poutre encastrée ; le kernel (AD-3, module serveur-only) analyse et affiche **lacunes, contradictions et erreurs** (trigger-map §7 signal 10, ADR §3). La preuve de compréhension (pas de cocher) est enregistrée comme `ProgressEvidence` (AD-9, F-07). En fin d'analyse, le **CTA fixe « Exercice progressif »** est le **seul CTA d'action** de la surface, vers `exercises` (01.6) — jamais une proposition libre de l'agent (invariant AD-14, Q8 passo 5).

La page ne fait qu'une seule chose : **vérifier la compréhension par l'explication (pas le QCM) et terminer par le CTA fixe vers l'exercice progressif**.

## 3. Mental State (step 12)

**Contexte de la page** : Horeb atterrit sur `/mirror` depuis le CTA fixe « Expliquer pour vérifier » du QCM (01.4), 23 h, thème Nocturne, réseau 3G instable. Elle vient de terminer le QCM (score ≥ 80 %, mais le score de transfert était inférieur au score de reconnaissance — le gap détecté par ADR §18.2).

| Dimension | Contenu |
|---|---|
| **Trigger** (ce qui la pousse) | Elle vient de voir que son score de **transfert** (7/10) est inférieur à son score de **reconnaissance** (9/10) au QCM (01.4) — elle veut **vérifier sa compréhension par l'explication** (pas un autre QCM) pour savoir si elle sait vraiment **transférer** la flèche d'une poutre encastrée à un cas réel (ADR §18.2, trigger-map §7 signal 7) |
| **Hope** | Expliquer la poutre encastrée à voix haute et **voir le kernel lui montrer ses lacunes** (pas juste valider ce qu'elle sait déjà) — la preuve qu'elle sait **transférer**, pas juste **reconnaître** (trigger-map §7 signal 8, ADR §18.3) |
| **Worry** | Que le kernel **ne détecte pas** sa lacune de transfert (faux négatif) et qu'elle reparte avec l'illusion « c'est bon » (peur ①, ADR §18.2, trigger-map §7 signal 7) ; et que l'analyse soit **trop longue** (le kernel analyse, ~30 s-1 min) et qu'elle perde patience (fatigue nocturne, ADR §23.1) |
| **Questions** | « Le kernel va-t-il détecter ma lacune de transfert ? » · « Combien de temps l'analyse prend-elle ? » · « Le CTA « Exercice progressif » est-il bien là à la fin de l'analyse ? » |
| **Contrainte UX** | La preuve de compréhension est **enregistrée comme `ProgressEvidence`** (AD-9, F-07) — pas un simple cocher (pas de QCM). Le kernel (AD-3, module serveur-only) **analyse et affiche** : lacunes, contradictions, erreurs (trigger-map §7 signal 10, ADR §3). **En fin d'analyse**, le CTA fixe « Exercice progressif » est le **seul CTA d'action** de la surface (invariant AD-14, Q8 passo 5) — jamais une proposition libre de l'agent. **Offline = état premier (AD-7)** : le kernel est un module serveur-only (AD-3) — si le réseau est coupé, l'analyse n'est pas disponible (pas de mirror local pour le kernel, contrairement aux flashcards). |

## 4. Desired Outcome (step 13)

### Business Goal
**Produire 1 `ProgressEvidenceCreated` (AD-9, F-07) qui prouve la compréhension par l'explication (pas le QCM)** — le miroir cognitif produit **≥ 1 preuve vérifiée** (l'analyse du kernel : lacunes/contradictions/erreurs) qui alimente le dashboard Progress (S-13, ADR §18.6). C'est la **3ᵉ preuve de la session** (après les flashcards S-19 et le QCM S-20), dans le contract de 4 preuves (S-19/20/22/38). Source : scenario 01 Q7 (Business Success : 4 `ProgressEvidenceCreated` attendus, 1 par surface de preuve), strategic-chains Chaîne 01 Q7, ADR §3, F-07.

### User Goal
**Vérifier sa compréhension par l'explication (pas le QCM) et voir le kernel lui montrer ses lacunes** — elle est **prête pour l'exercice progressif** (01.6) via le CTA fixe « Exercice progressif ». Source : scenario 01 Q4 (Hope), Q8 passo 5, trigger-map §7 signal 8/10.

## 6. Layout Structure (step 15)

*(PROPOSITION SUGGEST — à confirmer ; NON COUVERT par le corps gelé pour la disposition interne, dérivé de scope-report S-22 + trigger-map §4 Intent #6 + ADR §3)*

**Composition mirror-cognitive (S-22, session vocal + analyse kernel) — 3 zones fixes (pas un dashboard de widgets) :**

```
+-------------------------------------+
| Mirror-cognitive (thème Nocturne)   |
+-------------------------------------+
|  Zone 1 : Capture                  |
|  [Bouton micro] 🔴                 |
|  (ou textarea texte libre)          |
|  « Explique-moi la poutre encastrée |
|   en 2-3 phrases »                  |
+-------------------------------------+
|  Zone 2 : Analyse (post-capture)    |
|  +-------------------------------- |
|  | Lacunes détectées :             |
|  |  • Transfert → cas réel : gap   |
|  |  • Contradiction : flèche encastrée ≠ flèche simple |
|  | Erreurs : 1 (unités)           |
|  +-------------------------------- |
+-------------------------------------+
|  Zone 3 : CTA (fin d'analyse)      |
|  CTA FIXE : [Exercice progressif]  |
|  → `exercises` (01.6)             |
+-------------------------------------+
|  BottomNav (5 tabs, S-31 shared)   |
|  Home · Kanban · Calendar ·        |
|  Progress · /agent                 |
+-------------------------------------+
```

**Note** : Les 3 zones sont fixes (pas de widgets dynamiques, pas de proposition d'agent). La **Zone 1** est la capture (bouton micro ou textarea texte libre — l'explication est à voix haute ou écrite, pas un QCM). La **Zone 2** est l'analyse du kernel (AD-3, module serveur-only) : lacunes, contradictions, erreurs (trigger-map §7 signal 10, ADR §3) — **affichée après la capture**, pas pendant. La **Zone 3** n'apparaît **qu'en fin d'analyse** : le CTA fixe « Exercice progressif » est le **seul CTA d'action** de la surface (invariant AD-14, Q8 passo 5) — jamais une proposition libre de l'agent.

## 7. Page States (AD-13, 5 états canoniques)

| State | When | Appearance | Actions |
|-------|------|------------|---------|
| **Default** | Capture en attente (micro ou texte) | 3 zones : capture (bouton micro), analyse (masquée), CTA (masquée) | Tap sur micro → capture ; tap sur CTA (post-analyse) → `exercises` (01.6) |
| **Loading** | Analyse du kernel en cours (AD-3, module serveur-only, ~30 s-1 min) | Zone 2 : skeleton de l'analyse, CTA indisponible — **l'analyse n'est PAS disponible offline** (AD-7 : offline = état premier, mais le kernel est un module serveur-only) | — |
| **Empty** | Pas de capture (micro désactivé ou texte vide) | État vide actionnable : « Enregistre ton explication » + CTA micro/texte | Tap sur CTA → capture |
| **Error** | Échec de l'analyse du kernel | Message lisible « Erreur d'analyse » + CTA « Réessayer » (AD-13, A4 : erreur lisible, retry toujours disponible) | Tap sur « Réessayer » → re-lancer l'analyse |
| **Offline** (AD-7) | Réseau coupé, analyse non disponible (module serveur-only) | Bandeau fine « hors-ligne — analyse indisponible » (AD-13, A5), actions cloud désactivées **avec explicatif** (pas masquées) | Pas de CTA d'action (l'analyse n'est pas actionnable offline) ; retour natif vers /qcm (01.4) ou /progress (01.2) |
