## 3. Mental State (step 12)

**Contexte de la page** : Horeb atterrit sur `/exercises/:id` depuis le CTA fixe « Exercice progressif » du mirror-cognitive (01.5), 23 h, thème Nocturne, réseau 3G instable. Elle vient de voir que le kernel a détecté une lacune de transfert (la flèche de la poutre encastrée n'est pas appliquée à un cas réel).

| Dimension | Contenu |
|---|---|
| **Trigger** (ce qui la pousse) | Elle vient de voir que le kernel a détecté une **lacune de transfert** (la poutre encastrée n'est pas appliquée à un cas réel) — elle veut **vérifier son transfert par l'exercice progressif** (pas juste le QCM ou le miroir), pour prouver qu'elle sait **appliquer** (pas juste reconnaître), avec le Scientific Engine qui vérifie les unités/dimensions (trigger-map §4 Intent #6, ADR §18.3) |
| **Hope** | Obtenir l'exercice **validé par le Scientific Engine** (unités/dimensions conformes, `scientific.evaluate`/`scientific.verify`) — la preuve qu'elle sait **appliquer** la poutre encastrée à un cas réel de bureau d'études (cible mesurable Q7(b), trigger-map §4 Intent #6, ADR §18.3) |
| **Worry** | Que le **Scientific Engine ne valide pas** son exercice (unités/dimensions non conformes) et que la preuve `ProgressEvidence` ne soit pas produite — l'illusion de progression (peur ①, ADR §18.2) ; et que l'exercice soit **trop difficile** (progressif = plusieurs étapes, 3-5 sous-étapes) et qu'elle abandonne avant la validation (fatigue nocturne, ADR §23.1) |
| **Questions** | « Le Scientific Engine va-t-il valider mon exercice ? » · « Combien de sous-étapes ai-je déjà terminées ? » · « L'auto-redirect vers /progress va-t-il bien se déclencher ? » |
| **Contrainte UX** | L'exercice est **progressif** (pas un QCM) : plusieurs sous-étapes, chaque étape est vérifiée par le Scientific Engine (unités/dimensions, `scientific.evaluate`/`scientific.verify`). **La validation de l'exercice déclenche l'auto-redirect événementiel** vers `/progress` (pas un CTA manuel) — re-render du dashboard à l'événement `ProgressEvidenceCreated` (AD-9 → ProgressSnapshot, dashboard ADR §18.6). C'est le **seul mécanisme de sortie** de la surface (invariant AD-14, Q8 passo 6) — jamais un CTA manuel. **Offline = état premier (AD-7)** : le Scientific Engine est un module serveur-only (AD-12) — si le réseau est coupé, la validation n'est pas disponible (pas de mirror local pour le Scientific Engine, contrairement aux flashcards). |

## 4. Desired Outcome (step 13)

### Business Goal
**Produire 1 `ProgressEvidenceCreated` (AD-9, F-07) qui prouve le transfert par l'exercice progressif (Scientific Engine)** — l'exercice produit **≥ 1 preuve vérifiée** (la validation `scientific.evaluate`/`scientific.verify`) qui alimente le dashboard Progress (S-13, ADR §18.6). C'est la **4ᵉ preuve de la session** (après les flashcards S-19, le QCM S-20 et le miroir S-22), dans le contract de 4 preuves (S-19/20/22/38). Source : scenario 01 Q7 (Business Success : 4 `ProgressEvidenceCreated` attendus, 1 par surface de preuve), strategic-chains Chaîne 01 Q7, ADR §18.3, F-07.

### User Goal
**Obtenir l'exercice validé par le Scientific Engine et auto-redirect vers /progress** — elle est **prête pour le dashboard post-session** (01.7) qui affiche les 4 nouvelles preuves (S-19/20/22/38) dans les 5 questions (dashboard ADR §18.6). Source : scenario 01 Q4 (Hope), Q7(b) (exercice validé Scientific Engine), Q8 passo 6, trigger-map §4 Intent #6.

## 6. Layout Structure (step 15)

*(PROPOSITION SUGGEST — à confirmer ; NON COUVERT par le corpus gelé pour la disposition interne, dérivé de scope-report S-38 + trigger-map §4 Intent #6 + ADR §18.3)*

**Composition exercises progressifs (S-38, session vérifiée par Scientific Engine) — 3 zones fixes (pas un dashboard de widgets) :**

```
+-------------------------------------+
| Exercises (thème Nocturne)         |
+-------------------------------------+
|  Zone 1 : Progression              |
|  « Sous-étape 2/5 » (badge)        |
|  + domaine : RDM (poutre encastrée)|
+-------------------------------------+
|  Zone 2 : Exercice courante         |
|  +-------------------------------- |
|  | [Énoncé]                        |
|  | « Calcule le moment fléchissant  |
|  |  maximal d'une poutre encastrée  |
|  |  de 6 m sous charge uniforme     |
|  |  de 10 kN/m. »                  |
|  |                                  |
|  | [Saisie numérique]               |
|  |  Valeur : [____]                 |
|  |  Unités : [____]                 |
|  +-------------------------------- |
|  CTA : [Valider l'étape]          |
+-------------------------------------+
|  Zone 3 : Validation (fin)        |
|  Scientific Engine : VALIDÉ ✓     |
|  (unités/dimensions conformes,     |
|   scientific.evaluate/verify)      |
|  → AUTO-REDIRECT /progress (01.7) |
|  (événement ProgressEvidenceCreated)|
+-------------------------------------+
|  BottomNav (5 tabs, S-31 shared)   |
|  Home · Kanban · Calendar ·        |
|  Progress · /agent                 |
+-------------------------------------+
```

**Note** : Les 3 zones sont fixes (pas de widgets dynamiques, pas de proposition d'agent). La **Zone 1** affiche la progression (sous-étape 2/5) + le domaine (RDM : poutre encastrée). La **Zone 2** est l'exercice courant (énoncé + saisie numérique : valeur + unités) + CTA « Valider l'étape ». La **Zone 3** n'apparaît **qu'en fin de session** : la validation du Scientific Engine (unités/dimensions conformes, `scientific.evaluate`/`scientific.verify`) + **auto-redirect événementiel** vers `/progress` (01.7) — **pas un CTA manuel** (invariant AD-14, Q8 passo 6) : le re-render du dashboard est déclenché par l'événement `ProgressEvidenceCreated` (AD-9 → ProgressSnapshot, ADR §18.6).
