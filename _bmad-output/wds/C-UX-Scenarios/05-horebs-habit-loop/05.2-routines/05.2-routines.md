## 1. Page Purpose (step 10)

**Wording proposé (09/25) :**
> Horeb ouvre l'écran `routines` (S-09) depuis le tap sur la Card « Routine du soir » de `/habits` (05.1, S-08) et lit la **séquence ordonnée de son rituel nocturne** : `Révisions 30 min` → `Capture de notes` (numéro 1, 2 — l'ordre **est** la routine, pas un to-do ; pack 05 §4.3.6, `master-feature-catalog` L24). Elle déroule les étapes **dans l'ordre défini** : le tap sur chaque `RoutineStep` coche l'étape **inline** (pas de push, pas de confirmation — la régularité **se voit** dans le `ProgressBar` qui avance, pack §4.3.6). Le CTA **« Marquer l'étape »** est **unique par étape** (un tap, pas un formulaire, pack §4.3.6 ; garde AD-14 : jamais une proposition libre de l'agent dans le chemin court). La page ne fait qu'une seule chose : **montrer la séquence et la dérouler en gestes minimaux**.

## 3. Mental State (step 12)

**Contexte de la page** : 22 h 45, chambre, Pixel 4a, thème Nocturne, réseau 3G Bénin (AD-7, offline = état premier). Horeb vient de marquer le check-in du jour sur `/habits` (05.1) et veut **s'assurer que sa routine du soir a été réellement faite** — elle déroule les étapes de son rituel nocturne (révisions 30 min → capture de notes) dans l'ordre défini, et **confirme que la routine est complète** (toutes les étapes faites). Fatigue post-RDM, scénario 05 Q3.

## 4. Desired Outcome (step 13)

### Business Goal
**Régularité des routines mesurée (fidélisation) qui rend la transformation réelle (mesure, preuves) continue** — chaque check d'étape crée une **preuve de complétion traçable** (`ProgressBar` 100 %, `RoutineStep` cochées) ; le but n'est pas le compteur de tâches mais le **pattern de séquence bouclée** (scenario 05 Q2 BG-PRIMARY ; ADR §18.2 transformation dans le temps ; trigger-map §1 Primary ; ADR §2 cycle de productivité). Source : `master-feature-catalog` L24 (adherence analytics + routines temporal anchors), strategic-chains Chaîne 05 Q8 passo 2.

### User Goal
**Dérouler les étapes de sa routine ordonnée du soir dans l'ordre défini et confirmer que la routine est complète (toutes les étapes faites)** — le `ProgressBar` atteint **100 %** localement (AD-7, pas besoin de cloud), bouclant proprement le rituel nocturne sans y ajouter de widget ni attendre le réseau. Source : scénario 05 Q8 passo 2 (« elle confirme que la routine est complète (toutes les étapes faites) ») ; ADR §2.7 « Suivi de régularité ».

## 6. Layout Structure (step 15)

*(PROPOSITION SUGGEST — NON COUVERT par le corps gelé pour le rendu mobile exact de la séquence ordonnée `RoutineStep` 1 colonne ; dérivé de pack 05 §4.3.6 `routines` + §3.6.12 `RoutineStep` + strategic-chains Chaîne 05 Q8 passo 2 + scope-report S-09 §A #9)*

**Composition `routines` (S-09) — SegmentedControl famille + séquence ordonnée `RoutineStep` + `ProgressBar` (pas un to-do, pas un dashboard, pas un compteur de tâches) :**

+-------------------------------------+

**Note** :
- Chaque famille (Matin/Soir/Étude) = une **`SegmentedControl`** (le choix est **exclusif** et **ternaire**, pack §4.3.6 §3.4 — pas un select : le `SegmentedControl` est justifié ici car le choix est binaire/ternaire, pas un choix ouvert). Horeb est sur **Soir** (session nocturne 22 h 45, scénario 05 Q3).
- Chaque étape = un **`RoutineStep`** (§3.6.12 pack 05 : numéro `JetBrains Mono xs` + `Checkbox` + titre + durée estimée `JetBrains Mono xs`) — **pas une liste plate de to-do** (pack §4.3.6 : la routine est une **séquence**, le §2.7 « Routines matin/soir et routines d'étude »).
- Le **`ProgressBar`** (pack §4.3.6) montre le **% de complétion de la routine du jour** — la régularité **se voit** dans la barre qui avance, **pas dans un écran de confirmation** (le check est **inline** : tap sur `RoutineStep` = coche l'étape, pas de push, pas de BottomSheet de confirmation).
- **Aucun CTA global « Routine complète »** — la §4.3.6 ne mentionne pas de bouton de confirmation finale ; la complétion est **visuelle** (ProgressBar à 100 % + toutes les `RoutineStep` cochées). **OQ-3** : si un CTA est ajouté, il doit être **fixe** (AD-14 : jamais une proposition libre de l'agent dans le chemin court) et **non-actionnable** (un tap sur « Routine complète » n'ouvre pas un formulaire ni une BottomSheet d'analyse — c'est un badge de confirmation visuelle, pas une action).
- Transition : tap sur une `RoutineStep` **coche l'étape inline** (pas de push, pas de BottomSheet — pack §4.3.6 : le check est **inline**, la régularité se **voit** dans le `ProgressBar`). Le FAB ouvre la BottomSheet de création (pack §4.3.6).
- **Offline = état premier (AD-7)** : le check inline **ne doit pas exiger le réseau** (pack §4.3.6 `offline` : les routines restent **lisibles** (lecture locale), le « Marquer l'étape » reste **possible** (l'écriture est locale, pack 03 — une routine ne doit jamais exiger le réseau, AD-7)). La mutation entre dans la **queue for upsync** (03-sync §4.2) ; seule la ré-synchronisation distante est reportée.
