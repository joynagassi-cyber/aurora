## 1. Page Purpose (step 10)

**Wording proposé (09/25) :**
> Horeb ouvre l'écran `habitudes` (S-08) depuis le bloc « Habitudes/Routines » de Home AD-14 et lit l'**heatmap d'adhérence `HabitStreak`** (7 semaines mobile, scope-report variante §5 ; token `habit-weak` → `habit-med` → `habit-strong`, pack 05 §3.6.12) — **la régularité est mesurée, pas comptée** (trigger-map §7 signal 8 : toute progression significative reliée à des preuves ; ADR §2 cycle de productivité). Elle tape le **check-in quotidien « Marquer aujourd'hui »** (un tap unique, pas un formulaire — pack 05 §4.3.5) : la **brique du jour s'ajoute immédiatement** à sa chaîne (la première case se remplit sans cloud, AD-7 ; scope-report §A #8 ; `master-feature-catalog` L24). La page ne fait qu'une seule chose : **montrer le pattern d'adhérence et le boucler en 1 geste**.

## 3. Mental State (step 12)

**Contexte de la page** : 22 h 30, chambre, Pixel 4a, thème Nocturne, réseau 3G Bénin (AD-7, offline = état premier). Horeb vient de finir ses révisions post-cours RDM (fatigue post-RDM, scénario 05 Q3). Elle veut **s'assurer que sa routine du soir a été réellement faite** et boucler la journée proprement — sans ajouter un widget-dashboard (trigger-map §6 trap « Surcharge de widgets », AD-14).

| Dimension | Contenu |
|---|---|
| **Trigger** (ce qui la pousse) | Le bloc « Habitudes/Routines » de Home (AD-14) l'appelle au check-in du soir — elle veut **fermer la boucle du jour** : savoir si sa régularité (habitude « révisions 30 min ») tient (scenario 05 Q4 ; trigger-map §2 Envie ① Focus + ADR §2 cycle de productivité) |
| **Hope** | Voir son heatmap `HabitStreak` (7 semaines mobile, 7 briques consécutives) et **marquer le check-in du jour en 1 tap** — la brique 8 apparaît **immédiatement** (première case locale, AD-7, pas besoin de cloud) ; la régularité est **mesurée** (pattern + chiffre de streak), pas comptée (trigger-map §7 signal 8 ; ADR §2.10) |
| **Worry** | Que la page devienne un **simple compteur de tâches / une pile de rappels non suivis** (Veille passive, trigger-map §6 + §7 signal 20 « Tendances de procrastination » ; ADR §2.10) — ou que le check-in **demande le réseau** (contradiction AD-7) et l'empêche de boucler sa journée en 3G instable |
| **Questions** | « Ma chaîne tient-elle cette semaine (7 briques) ? » · « Le check-in du jour est-il déjà marqué ? » · « Le tap unique suffit-il, sans formulaire ? » |
| **Contrainte UX** | La heatmap `HabitStreak` affiche **7 semaines (mobile)** avec 5 niveaux de teinte (token `habit-weak`/`habit-med`/`habit-strong`, §3.6.12 pack 05) et **pas d'animation de remplissage** (règle 1 §2.6 pack 05 : les cellules *sont*, elles ne se peignent pas). Le CTA **« Marquer aujourd'hui »** est **unique et fixe** (un tap, pas un formulaire, pack §4.3.5 ; garde AD-14 : jamais une proposition libre de l'agent dans le chemin court). Le **streak courant** (ex. « 12 jours ») s'affiche en `JetBrains Mono` `lg` à côté — **le chiffre parle, la heatmap est la preuve**. **Offline = état premier (AD-7)** : l'écriture est **locale** (PowerSync mirror, pack 03), le check-in **ne doit pas exiger le réseau** ; la liste et le CTA restent fonctionnels, seule la ré-synchronisation distante est reportée. |

## 4. Desired Outcome (step 13)

### Business Goal
**Régularité mesurée (fidélisation) qui rend la transformation réelle (mesure, preuves) continue** — chaque check-in crée une **preuve d'adhérence traçable** (heatmap `HabitStreak`) ; le but n'est pas le compteur de tâches mais le **pattern visible** (scenario 05 Q2 BG-PRIMARY ; ADR §18.2 transformation dans le temps ; trigger-map §1 Primary ; ADR §2 cycle de productivité). Source : `master-feature-catalog` L24 (adherence analytics), strategic-chains Chaîne 05 Q6.

### User Goal
**Voir son heatmap `HabitStreak` (7 semaines mobile) et marquer le check-in du jour en 1 tap** — la brique du jour s'ajoute à sa chaîne **immédiatement** (AD-7 local), bouclant proprement la routine du soir sans y ajouter de widget ni attendre le réseau. Source : scénario 05 Q4 (Hope), Q8 passo 1 ; ADR §2.7 « Suivi de régularité ».

## 6. Layout Structure (step 15)

*(PROPOSITION SUGGEST — NON COUVERT par le corps gelé pour le rendu mobile exact du heatmap 7 semaines ; dérivé de pack 05 §4.3.5 `habitudes` + §3.6.12 `HabitStreak` + strategic-chains Chaîne 05 Q8 passo 1 + scope-report S-08 §A #8)*

**Composition `habitudes` (S-08) — liste d'habitudes = une `Card flat` par habitude + CTA fixe « Marquer aujourd'hui » (pas un dashboard, pas un compteur de tâches) :**

```
+-------------------------------------+
| /habits (thème Nocturne, sombre)    |
| TopBar : « Habitudes » + Menu       |
|   [ Routines ] [ Adhérence ]        |
+-------------------------------------+
|  Card flat : habitude « Révisions » |
|  Titre : « Révisions 30 min »       |
|  HabitStreak (heatmap, 7 semaines   |
|    mobile, 7 colonnes × 7 sem.,    |
|    cellules 12×12 px, 5 niveaux,   |
|    SANS animation de remplissage)   |
|  Streak courant : « 12 jours »      |
|    (JetBrains Mono lg — le chiffre  |
|    parle, la heatmap est la preuve) |
|  [ CTA FIXE : Marquer aujourd'hui ] |  ← tap unique, écriture locale AD-7
+-------------------------------------+
|  Card flat : habitude « Routines »  |
|  Titre : « Routine du soir »        |
|  HabitStreak (7 semaines mobile)    |
|  Streak courant : « 7 jours »       |
|  [ CTA FIXE : Marquer aujourd'hui ] |
+-------------------------------------+
|  (liste continue — scroll vertical) |
+-------------------------------------+
|  FAB : « + Créer une habitude »     |
|    (BottomSheet de création :        |
|     TextField titre + Segmented     |
|     « quotidien / hebdo » + Select  |
|     d'heure)                        |
+-------------------------------------+
|  BottomNav (5 tabs, S-31 shared)    |
|  Home · Kanban · Calendar ·         |
|  Progress · /agent                  |
+-------------------------------------+
```

**Note** :
- Chaque habitude = une **`Card flat`** (titre + `HabitStreak` + CTA « Marquer aujourd'hui » + `KeyValueList` compact du streak courant) — **pas un dashboard, pas un compteur** (trigger-map §6 trap « Surcharge de widgets », pack 05 §4.3.5).
- `HabitStreak` = grille **7 colonnes (jours) × 7 semaines (mobile)**, cellules 12×12 px, 5 niveaux de teinte (`habit-weak`→`habit-med`→`habit-strong`, §3.6.12 pack 05), niveau 0 = `bg-subtle`, **sans animation de remplissage** (règle 1 §2.6 : les cellules *sont*, elles ne se peignent pas).
- CTA **« Marquer aujourd'hui »** = **tap unique** (pas un formulaire, pack §4.3.5) ; écriture **locale AD-7** (la première case se remplit immédiatement, pas besoin de cloud) ; le check-in **ne doit pas exiger le réseau** (pack §4.3.5 `offline`).
- Streak courant affiché en `JetBrains Mono` `lg` (ex. « 12 jours ») — le **chiffre parle**, la heatmap est la **preuve** (§3.6.12 pack 05).
- Transition : tap sur une Card → **BottomSheet d'analyse** (Timeline des reports + `HabitStreak` étendues 12 mois + « routines perturbatrices » qui la ciblent — pack §4.3.5 ; l'habitude « lire » est perturbée par la routine « écran le soir », ce lien est *affiché*, pas un « insight » mystérieux). Le FAB ouvre la BottomSheet de création (pack §4.3.5).
