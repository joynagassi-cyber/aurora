# 02 — Detect lens B: inert / fake-at-runtime UI states (apps/mobile)

## Summary

**Total: 5 findings — 2 High, 1 Medium, 2 Low.** All are UI states that render a working-looking control whose click resolves to nothing observable (or to a value that silently dies). The highest-value lens target — the `/focus` page mounted `service={null}` — turned out to be **visibly degraded, not silently broken**: the start button is disabled by design, which is why it ranks Medium rather than High. The two High findings are the agent page's fake-file button (functionally void, not just cosmetic) and the inbox "Capturer" button that erases the user's text and then shows "Inbox vide — tout est classé".

## Verdicts on the four directed questions

1. **`/focus` with `service={null}` (`router.tsx:90`) → Medium.** The user does **not** see a silently-broken timer: the start button is explicitly `disabled` (`focus/index.tsx:304`) and the live-timer row degrades to a visible `—` (`index.tsx:320-322`). But it also does **not** render the 04 S4.2 "Focus not configured / DPC not provisioned" fallback — the two `data-state` fallback branches (`restriction-fallback` / `dpc-available`, `index.tsx:146-157`) both require `service` truthy, and `service === null` makes `blocking` short-circuit to `false` without rendering anything (`index.tsx:74-84`). Net: visibly degraded config form + dead CTA, no honest label. Not High (nothing *looks* broken silently), but a real premium-audit gap.
2. **Fake files (`agent/index.tsx:454-464`) → High.** Confirmed: no `type="file"` anywhere in `src/**`; the fake `fichier-N.pdf` names are **dropped** — `AgentRunRequest` (`lib/agent-client.ts:34-49`) has no `files` field, only `contextRefs?: string[]` (never populated) — and `submit()` clears the array before sending (`index.tsx:155`). So this is not cosmetic: the chip promises a control that is functionally void.
3. **`MODEL_CATALOG` vs server (agent/index.tsx:39-44) → NOT a finding (verified clean).** `TaskProfile` does expose `preferredProvider?/preferredModel?` only as optional picker outputs (`packages/agent/src/types.ts:49-50` — and the picker writes nothing else; the other profile fields flow from the same UI, which is honest). The S2.6 router **honors** the pin: `router.ts:107-120` pushes the preferred provider/model as `primary` of the chain, with AD-5 fallback still applying. The device catalog is byte-identical to `PROVIDER_MODEL_CATALOG` in `supabase/functions/_shared/fn-agent-bootstrap.ts:64-84`, and every listed model name exists in the frozen S2.6 registry (`packages/agent/src/router.ts:203,213,220-229`: `agnes-3.0`, `glm-4.7-flash`, `gemma-4-26b`, `nemotron-3-super-120b`, `gpt-oss-120b`, `gpt-oss-20b`, `nemotron-3-ultra`, `gemma-4`). Caveat (not a finding): `fn-agent-bootstrap.ts:152-168` `modelPicker()` hides providers whose key is absent — the device's static catalog can advertise a provider that is pinned-but-ineligible server-side, where the router then just falls back to primary; the doc-comment already discloses this behavior (`types.ts:41-47`).
4. **Other inert click targets → findings #4 and #5.** Swept all `onClick`/`onSubmit` in `src/pages/**`: ascent retry (`refetch`), skills toggles/create/delete (`fn-skills` verbs, all real), integrations toggles (`fn-integrations.connect` + re-read, real), settings swatches/local state, calendar/task/period segmented controls (state switch), task/goal detail navigation, goals node-tap → `/goals/:id/features/:fid` (routed) — all observable. The only silent-click cases are the two above. The `/goals/:id/features/:fid` destination is a static placeholder (`goals/index.tsx:129-155`) — reachable but not itself an inert-state defect; noted for completeness.
