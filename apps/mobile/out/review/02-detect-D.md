## 🔴 (low-confidence) findings — user question

The two items I could not fully verify from source alone, flagged 🔴 in the table:

1. **D2 (mutual exclusion of the two agent dialogs)**: I confirmed `showPicker` and `showPlusSheet` are independent `useState` flags and that the + sheet's "Skills" button `navigate`s to `/skills` (unmounting the page). I did **not** verify at runtime that React's `navigate` can ever leave both flags true in the same render (e.g. if the route change is cancelled or slow). Question for the user: *"Can the user open the model picker and then, while it is open, tap the + sheet trigger — or is the + sheet only reachable from a state where the picker is closed?"* The answer determines whether D2 is a real double-modal risk or a non-issue.

2. **D5 (floating.tsx focus target)**: I read the source and it focuses `scrimRef` (the outer scrim div), not the inner `.aurora-sheet` menu. I have not runtime-verified whether focusing a `tabIndex={-1}` scrim actually moves DOM focus or whether the browser refuses it on a non-focusable-by-default `div`. Question: *"In a real WebView, does `scrimRef.current?.focus()` actually move keyboard focus to the scrim, or does it silently no-op?"* If it no-ops, the trap is even weaker than the source suggests.
