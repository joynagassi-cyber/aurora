## 4. États (S6 + sémantiques §6.1) — par élément async

**Règle d'état** (05 §4.3.4 l. 1664-1679) : `loading`/`empty`/`error`/`offline` = **identiques** à `projets-detail` §4.3.2 (le pattern est **le même**, les types sont différents — `Objectif` vs `Projet`, AD-15 ; le DS est **agnostique** du type métier) ; le **miroir local** = AD-7 (lecture **toujours** lisible) ; le mission-control **n'a pas** de flux serveur au mount (le replan = mutation **locale**, S5 l. 278-285) ; le **seul** flux serveur = le deep link `/agent` du context strip (index.tsx l. 109-112, §12). WDS 02.3 §7 (l. 148-152) donne les **5 états** de page (AD-13) : Default / Loading / Empty / Offline / Error.

## 8. Pagination

**Règle unique nommée** : le mission-control nest **pas** une liste paginée — cest un **spatial layout** (goal-dashboard-ui S2 l. 55-80 : « a full-screen, goal-specific mission control », pas une liste de features). Les features sont **bornées** (S8 l. 315-317 : « n = number of features, typically 4-12, never > 20 in V1 »), donc **aucune pagination ni virtualisation** nest nécessaire (ui-libraries S8 l. 304-307 : le seuil de pagination est 20 lignes, le V1 **nexceed jamais** 20). Le layout est **calculé O(n)** (S8 l. 315-317), le rendu < 100 ms (S8 l. 313-315) — le volume est **très en dessous** du seuil de virtualisation (ui-libraries S8 l. 289-291 : > 100 = AG Grid, **jamais** atteint ici).

Le pattern 05 §4.3.4 (la liste des jalons RoutineStep + la liste des projets contributeurs KeyValueList) **pourrait** théoriquement dépasser le seuil (un objectif avec beaucoup de jalons ou de projets) — le SSoT **ne tranche pas** si une pagination est nécessaire pour ces listes si elles sont présentes (cest lié à OQ-1 : si le pattern 05 est rendu en plus du mission-control, le seuil de pagination sapplique aux listes RoutineStep/KeyValueList ; si seul le mission-control est rendu, **aucune** liste paginée n'existe). = **OQ-5** (responsive + pagination, lié à OQ-1).
