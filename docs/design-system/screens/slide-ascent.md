# Écran : slide-ascent — Slide ascent (palette 12 types de slides)

> Module Ascent · Route `/goals/:id/ascent` (router.tsx l.85, `SlideAscentPage`, détail ouvert **sur** l'onglet courant, 02 §6.1 S1/S3) · SSoT `docs/ascent/overview.md` S11–S14 + WDS S-41 (cf. `_inventory.md` #45) · Statut : additif
> Classe offline (catalog) : **offline-capable (lecture du goal, mirror)** — l'écran lit **uniquement** le miroir local `ascent_paths` (PowerSync scope « ascent », `supabase/migrations/0016_ascent.sql` + `powersync/schema.json` l.57–89) ; les adaptations (AscentAdaptation) sont calculées **côté serveur** (AD-12, 03 §4.2) → l'écran ne rend que la **lecture** hors-ligne, jamais l'écriture ni l'adaptation.

## §1 Psychologie designer

- **Objectif utilisateur** : traverser son **trajectoire pédagogique adaptative** (ce qu'Aurora a déterminé comme « à apprendre ensuite » pour l'objectif courant) par **progrès progressif** — voir le concept **maintenant** (Level 1 = étape courante + suivante, `docs/ascent/overview.md` S11), **pas** toute la trajectoire d'un coup (S11 « The user should never be overwhelmed by the full path on first load »). L'écran **résout** : « en quel ordre, à quel rythme, à quelle profondeur dois-je apprendre ça, et qu'est-ce que je fais **maintenant** ? » — l'écran affiche la **vue** (slides) d'une donnée qui est la source de vérité (`AscentLearningIR`), pas l'engin lui-même (S12 : « the slides are rendering », l'Ascent = l'engin qui **produit** la donnée, Slide-Ascent = le **rendu**).
- **Contexte** : mobile, main libre ; écran **additif** (module Ascent = NEW, `docs/ascent/overview.md` §2 : « No existing module is modified »), ouvert depuis l'objectif courant (`/goals/:id`, cf. WDS S-41 entry) ; **réseau** = l'écran lit le **miroir local** (AD-7/AD-12, mobile-first offline **required** contrairement à `expert_skills` qui n'est jamais mirroré — `apps/mobile/src/pages/ascent/index.tsx` l.5–10) ; **pas** de flux serveur direct (le serveur ne pousse **rien** ici : c'est le miroir qui est la surface de lecture, `0016_ascent.sql` « the read-only device mirror reads THROUGH this policy via v_ascent_scope »).
- **Fréquence** : **par session de révision** (l'écran est ré-ouvert à chaque reprise de la trajectoire ; Level 1 est **toujours visible** = « ce qui reste à apprendre maintenant », S11 Level 1) ; fréquence = cadence de la trajectoire (non définie ici, cf. §14 OQ-04) ; chaque session = lecture courte (pas de longue session, cf. `docs/ascent/overview.md` S11 « show the information when it becomes useful. Not before »).
- **État émotionnel cible** : **clarté progressive** (pas de surcharge, S11), **confiance** (la profondeur est **choisie** par Ascent avec justification, S13 : « the depth is selected by Ascent based on the goal's requirements / the learner's current state / time available »), **calme** (pas de 12 slides forcées, S12 : « Never impose 10 slides per course. The number of slides = the number of meaningful transitions in the path »), **transparence pédagogique** (source-hierarchy badge A>B>C>D, S16 : « Level D NEVER overrides Level A/B/C », le conflit **n'est jamais silencieux** — `apps/mobile/src/pages/ascent/slide-types.ts` l.100–106 « the conflict is NEVER silent »).
- **Erreur la plus probable** : confondre l'écran avec un **parcours séquentiel rigide** (attendre que les 12 types de slides soient forcés) alors que S12 dit explicitement « a PALETTE, not a mandatory sequence » — le nombre de slides = le nombre de transitions significatives de la trajectoire (S12 : « A 5-concept path might use: Concept, Formula, Example, Question, Recap ») ; ou **attenter de l'adaptation en temps réel** (les adaptations sont **côté serveur**, AD-12/F-09 : l'écran lit le **dernier** miroir, il **n'exécute** pas l'adaptation locale, `apps/mobile/src/pages/ascent/index.tsx` l.3–10 « No own SQL on the device (AD-7: Ascent is the single writer; the mirror is the read surface, AD-12: the device only reads the local mirror / AgentRunState) »).
- **Ce que l'écran RÉSOUT** : rendu par **slides** (palette 12 types, S12) d'un `AscentLearningIR` (miroir local, 0016), avec **progressive disclosure** (S11 Level 1–4), **badges de profondeur** (S13 : Quick/Standard/Deep) + **badge de hiérarchie source** (S16 : A>B>C>D, conflit jamais silencieux), et **5 actions de lecture active** (S14 : Explain / Note / Flashcard / Visualize / « Je bloque ») — avec les 6 états S6 (loading/empty/error/success/offline/killed, §4) + 404/not-found (§4c).

## §2 Contexte fonctionnel

- **Entrées** : l'objectif courant `/goals/:id` (WDS S-41 entry, cf. `goal-feature-detail.md` + `_inventory.md` #45 : « Ascent … route `/goals/:id/ascent` ») ; **deep-link** depuis le bloc de l'objectif (cf. `objectifs-liste.md` §2, si SSoT, cf. §14 OQ-05) ; **Sorties** : l'activité elle-même = déléguée à **Learning** (QCM/flashcards, `docs/ascent/overview.md` S3 : « Ascent does NOT generate QCMs … It tells Learning: "generate a QCM on concept X" ») ; l'épreuve = **Progress** (evidence, S4 « Ascent does NOT compute evidence. It reads Progress ») ; le contenu = **Knowledge** (concepts/formules, S4 « Ascent does NOT store concepts or formulas. It references them by ID ») ; retour arrière **conserve** la trajectoire (miroir local persisté, AD-7).
- **Async** : **flux miroir local uniquement** — l'écran lit **uniquement** le miroir `ascent_paths` (PowerSync, 03 §4.2, 0016 ; `apps/mobile/src/pages/ascent/index.tsx` l.41–63 `currentPathFromMirror` : « Offline-safe — a stale mirror is a frozen path, never an error state ») ; **pas** de flux serveur direct (AD-12 : les adaptations sont **côté serveur**, l'écran **consomme** le miroir, pas l'engin) ; **pas** d'exécution locale (règle 1 du §2.6 : scientific data jamais animée — ici **aucun** renderer AD-10 **dans l'écran lui-même** : les slides sont des **vues** sur la donnée, le rendu des formules/diagrammes est délégué aux **renderers** AD-10 du §11, pas re-dessiné ici, cf. §11).
- **Permissions** : l'écran **ne possède** pas les données (Ascent lit **via** les ports publics Knowledge/Progress/Discovery/Learning, `docs/ascent/overview.md` S7 : « Ascent reads from Knowledge, Learning, Progress, and Discovery via their public contracts. It NEVER writes to their tables ») ; **Feature disabled** (G-M7, cf. `apps/mobile/src/pages/ascent/index.tsx` l.67–71 `learningEnabled` : « the Flashcard action is only available when the Learning feature is enabled ») : si `learning` est désactivé par feature-registry → l'action **Flashcard** est **désactivée** (pas l'écran entier, l'écran **reste** lisible, cf. §12) ; si le **goal** n'existe plus (supprimé) → 404/not-found (§4c).
- **Feature disabled (404)** : si `/goals/:id/ascent` mène à un goal **inconnu** ou **supprimé** → l'écran rend `data-state=feature-disabled` + CTA re-enable (cf. `apps/mobile/src/pages/not-found/index.tsx` : « a deep link into a disabled feature renders a dedicated state, NEVER a crash or a 404 ») — **jamais** un crash/404 brut.
