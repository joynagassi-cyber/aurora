# Écran : fiches-liste — Fiches (liste)

> Module Learning · Route `/learn/:id` (overlay IonModal sur le tab courant, 02 §6.1 S1/S3 detail-over-tab, router.tsx) · SSoT 05 §4.7.1 l.2564–2639 (doc §17, 7 structures ADR) · Statut : détaillé

## §1 Psychologie designer

- **Objectif utilisateur** : retrouver rapidement une fiche de révision (par concept ou matière) et lancer sa génération si elle n'existe pas encore — la fiche est « conçue pour mémoriser, retrouver et réutiliser les connaissances réellement apprises », fidèle au corpus (05 §4.7.1 Objectif).
- **Contexte** : mobile, main libre, réseau patchy probable ; sessions de révision de 5–20 min ; ouverture depuis `cours-detail` ou `qcm` (score faible, 05 §4.7.1 Transitions) ; overlay = l'utilisateur reste dans son flux.
- **Fréquence** : plusieurs fois par semaine (révisions) ; la **génération** de fiche est **rare** (job serveur, AD-8/AD-12), la **lecture** est quotidienne (AD-7 local).
- **État émotionnel cible** : orientation (je vois quelles fiches j'ai déjà), confiance (mon contenu existe même offline), motivation (une seule action = générer/revoir).
- **Erreur la plus probable** : chercher un concept dans la SearchBar alors que la fiche n'a pas encore été générée (état empty par concept, 05 §4.7.1 empty → CTA actionnable) ; attendre un job de génération longue sans feedback (le FAB disparaît, l'écran passe en `loading` du contenu, 05 §3.1 l.409–410).
- **Ce que l'écran RÉSOlut** : inventaire local des fiches (lecture AD-7 SQLite, 100 % offline) + recherche par concept locale (AD-7) + **un seul** point d'entrée serveur = la génération (FAB « Générer une fiche », AD-12, différable offline, 05 §4.7.1 offline).

## §2 Contexte fonctionnel

- Entrée : depuis `cours-detail` (§4.7.1.2) ou depuis `qcm` (§4.8.2, après un score faible : « revoir la fiche », 05 §4.7.1 Transitions l.2626–2628) ; sortie : vers `fiches-detail` (§4.7.1, tap d'une `ListItem`), vers `flashcards` (§4.8.1, via « Envoyer vers FSRS » depuis la fiche), ou vers l'écran de visualisation d'un artefact (l'export §4.6.1) ; retour arrière conserve l'état (store UI pack 02 §3.2, AD-7 persist).
- Overlay IonModal `/learn/:id` (router.tsx, 02 §6.1 S1/S3) : le tab courant reste sous l'overlay (pas de navigation destructive).
- Data : `Learning` (doc §17) — une fiche = **job serveur** de génération (AD-8 : les traitements lourds ne bloquent pas l'UI) puis **stockage local** (AD-7 : générées puis stockées, 05 §4.7.1 offline l.2622–2623) ; la liste + la recherche = **lecture locale** (SQLite), le **seul** flux serveur de l'écran = la génération (AD-12 : l'agent exige le cloud pour l'IA).
- `learning.sheet` (feature-registry, _inventory l.109) : la **génération** est online-required ; la **lecture** est offline (AD-7 miroir local).
- Fidélité (AD-11, doc §17) : une fiche n'est pas un résumé — l'agent sélectionne l'une des **7 structures** (définitions / formules / méthode / comparative / procédure / synthèse / exercices, 05 §4.7.1 l.2571–2573) ; le type apparaît comme `Badge` dans la liste.

## §6 Tokens (discipline AD-17, 05 §2 l.93–346 + ui-libraries S4 l.145–160)

- **Aucune valeur brute** : pas de hex, pas de px de spacing/typo/radius codé en dur — toujours via variables CSS `hsl(var(--aurora-*))` (05 §5.2/5.3, ssootCode tokenRefs aurora.css) ; spacing = `aurora.space.*` (05 l.240), radius = `aurora.radius.md` 8px / `lg` 12px FAB (05 l.261–262), élévation = `aurora.shadow.1/2` (05 l.276–277), typo = Inter + JetBrains Mono (ssootCode themeRefs aurora.css).
- **Règle bloquante 05 §5.1 (l.2931)** : le thème ne touche **jamais** success/warning/danger/info (frozen semantic tokens) — le Callout warning (error row), le Badge offline (warning) et la bannière killed (danger) consomment ces tokens **sans jamais les redéfinir par thème**.
- **10 thèmes + 3 presets = comportement par couche** (05 §5.2 l.2961, ssootCode themeRefs) : l'écran ne code **aucune** valeur par thème ; pas d'override local (le seul L3 = Focus, OQ-15, ssootCode themeRefs theme-adapter.tsx).
- **focus visible** : le thème owns focus-ring (aurora.json focusTreatment = ring, ssootCode a11yRefs) — pas de gestion manuelle du focus par écran.
- **icônes** : 05 §2.5 l.287 — lucide (ssootCode paginationRefs Chevrons/MoreHorizontal) ; **pas** de custom SVG decoration (S3 l.141 interdit).
- **coins** : radius ≤ 8px (S3 l.142 interdit > 8px) ; le FAB = `aurora.radius.lg` (12px, 05 l.262 — spécifique FAB, **pas** une violation globale).
