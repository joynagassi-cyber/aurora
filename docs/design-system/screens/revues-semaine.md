# revues-semaine — Revues (semaine)

Status: SPÉCIFIABLE (OQ: 10) · Module : Productivité · Route : (reviews) · SSoT : 05 §4.5.1 l. 2229-2409 + WDS 06.1 + 05 §3.4 `Pager` l. 737-750 + 05 §3.7 l. 1244-1309 + ui-libraries S1/S3/§6/§9 + master-feature-catalog l. 26 (`productivity.reviews`, offline-capable)

> Le `revues-semaine` = le **mode « Semaine »** du `Pager` §3.4 (Jour | Semaine | Mois) de l'enveloppe `reviews` (enveloppe #52, inventaire l. 129). Une revue = **une `Card` posée** (pas un `ListItem`) : 5 sections (bilan des tâches / analyse des causes / révision des priorités / plan d'action suivant / journal des décisions), 05 §4.5.1 l. 2264-2310. Ce doc spécifie la zone de contenu en mode semaine ; les zones partagées (TopBar + Pager, BottomNav, 404, offline global) sont référencées vers l'enveloppe et non dupliquées. Le slug `retro-actions` (WDS 06.3) est **distinct** (rétrospective post-bouclée) — cf. OQ-1.

## 2. Zones

- **header** : `TopBar` « Revue » (05 §3.4 l. 659-668) + `Pager` §3.4 (Jour | Semaine | Mois, l. 737-750) + `SegmentedControl` « À faire / Faite » (l. 2249-2263 : statut `Review` AD-15 `pending`/`completed`). Ce doc = le **mode Semaine** du `Pager`.
- **content** : une `Review` = une `Card` **posée** (l. 2264-2276), 5 sections (l. 2277-2310) :
  1. `Bilan des tâches` — `DataTable` §3.6.1 (4 colonnes : statut / titre / projet / « pourquoi », l. 2280-2287)
  2. `Analyse des causes` — `TextArea` + `Badge` d'hypothèse ; 3 `Chip` de causes courantes (charge / fatigue / blocage technique, l. 2299-2310)
  3. `Révision des priorités` — liste `RoutineStep` ordonnée (l. 2288-2291)
  4. `Plan d'action suivant` — liste `RoutineStep` (l. 2292-2294)
  5. `Journal des décisions` — `TextArea` texte libre (l. 2295-2298)
  + `Callout warning` « revue en retard » posé si la revue de la période précédente n'a pas été faite (l. 2323-2330)
- **footer** : `BottomNav` (5 items figés, 05 §3.4 l. 670-688)
- **Surfaces flottantes** : `BottomSheet` de **création** de revue (état `empty`, l. 2338-2347) ; `Toast` (feedback) ; `Callout info` (reconnexion, killed).
- **Breadcrumb** : **n'existe pas** — la revue est une **feuille** du module Productivité (pas de hiérarchie AD-6).

### 4c. `killed` (tout flux serveur)

Le seul flux serveur = la **re-synchronisation** de la `Review`/`Decision` (AD-8, Job persisté ; 05 §4.5.1 l. 2353-2367 : « une revue **n'exige jamais** le réseau »). `killed` (G-M2) = `Skeleton` + bannière fine DS « Reconnexion… » (05 §3.7 l. 1290-1296 ; ui-libraries §6 l. 185) : le contenu du mirror local s'affiche (AD-7), le composant repasse en état normal quand le resync s'achève (l. 1292-1296). La **création** reste possible en `killed` (écriture locale, pack 03, l. 2355-2357).

## 8. Pagination

**Règle unique nommée** : `Pager` jour-semaine-mois (05 §3.4 l. 737-750) — le `Pager` **est** la pagination **temporelle** de ce slug (`SegmentedControl` `Jour | Semaine | Mois` + ligne de navigation précédent/suivant + « Aujourd'hui »).

- **Pas de shadcn `Pagination` ni `AG Grid`** : le volume = **borné** par la période (1 semaine ; les 5 sections = un nombre **fixe** d'éléments — le `DataTable` bilan ≤ 20 lignes typiquement, ui-libraries S8 l. 304-307 : < 20 rows → `Table`, pas de `Pagination` ; > 100 = `AG Grid` mais le bilan d'une **semaine** ne dépasse jamais le seuil).
- **Params** : le mode du `Pager` (Jour/Semaine/Mois) et l'ancrage temporel sont **persistés** par l'écran (store UI pack 02 §3.2, 05 §3.4 l. 743-745) — le retour retrouve le **même** mode + la **même** position (règle de non-surprise, l. 745).

## 12. Offline

- **Classe offline** (master-feature-catalog l. 26) : `productivity.reviews` = **offline-capable** (daily/weekly/monthly + decisions journal ; agent `review.run` = CONFIRMATION_REQUIRED).
