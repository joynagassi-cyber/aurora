# Écran : mirror-cognitive — Mirror cognitif (Learning)

> Module Learning · Route `/mirror` (enveloppe overlay IonModal, 02 §6.1 S1/S3, router.tsx pattern) · SSoT 05 §4.9.2 l.2840–2924 + WDS 01.5 + docs/learning/overview.md §21 (G-L3 closed 2026-09-22, 01-backend §4.2) · Statut : détaillé
> Classe offline (catalog `learning.mirror`) : **PARTIAL** — saisie = **locale** (AD-7), analyse = **serveur** (AD-12/F-09, kernel Tutor) ; offline → saisie archivée, analyse différée

## §1 Psychologie designer

- **Objectif utilisateur** : **révéler** (pas « noter ») — vérifier la compréhension : l'utilisatrice **explique** une notion (texte `TextArea` ou vocal), l'app **analyse** (kernel serveur, AD-12/F-09) et **affiche** les lacunes, contradictions et erreurs détectées + une **prochaine action concrète** (doc §2.3 « l'agent explique sa recommandation ») — 05 §4.9.2 « le mirror-cognitive est une **vérification** de la compréhension ».
- **Contexte** : mobile, main libre, réseau instable probable ; ouverture depuis `fiches-detail` (§4.7.1) ou `cours-detail` (§4.7.1.2) via le bouton « Vérifier ma compréhension » ; overlay = l'utilisatrice reste dans son flux (pas de navigation destructive). Sessions nocturnes possibles (thème Nocturne, 05 §5.5).
- **Fréquence** : à chaque notion révisée (plusieurs fois par semaine) ; l'analyse est un `ProgressEvidence` (doc §18.3 « explication personnelle », AD-9/F-07 : **jamais** créé directement par Learning).
- **État émotionnel cible** : curiosité (révélation, pas notation — l'écran **n'affiche pas** un score), confiance (prochaine action lisible, « réviser cette fiche / ce cours »), calme (pas de frustration si des erreurs sont détectées : Callout warning/danger lisible + correction fidèle au corpus, AD-11), motivation (prochaine action concrète, doc §2.3).
- **Erreur la plus probable** : attendre une analyse alors que le **cloud est indisponible** (AD-4, kernel serveur AD-12/F-09) → `Callout info` « l'analyse sera exécutée à la reconnexion, la saisie est archivée dans le store local » (05 §4.9.2 état `offline`) ; ou croire que le texte est perdu en quittant l'écran (AD-7 : la saisie est **persistée** localement, l'exit/retour ne perd rien, pack 02 §3.2).
- **Ce que l'écran RÉSOUT** : surface de **saisie libre** (texte + vocal, 05 §4.9.2 zones « Saisie libre ») + **résultat de l'analyse** (Callout info = concepts compris, Callout warning = lacunes, Callout danger = erreurs factuelles, chaque Callout pointe vers une fiche §4.7.1 ou un cours §4.7.1.2) + **actions flottantes** (Button primary « Lancer l'analyse » + Button ghost « Réessayer »). L'analyse est un `Job` asynchrone **côté serveur** (AD-8/F-09), l'app **n'exécute pas** l'analyse.

## §2 Contexte fonctionnel

- **Entrées** : CTA « Vérifier ma compréhension » depuis `fiches-detail` (§4.7.1) ou `cours-detail` (§4.7.1.2) ; deep link `/mirror` (push notification, automatisation). **Sorties** : `fiches-liste` (§4.7.1, « réviser les lacunes détectées ») ou retour arrière à la fiche/cours ; la saisie (texte/voix) est **persistée** localement (AD-7 : le re-sync est différé, l'exit/retour ne perd rien, pack 02 §3.2).
- **Overlay IonModal `/mirror`** (router.tsx detail-over-tab rule, 02 §6.1 S1/S3) : le tab courant reste sous l'overlay.
- **Data** : l'analyse est un `ProgressEvidence` (doc §18.3 : les preuves de compétence incluent « explication personnelle ») ; le `ProgressEvidenceCreated` est émis **par Progress**, **jamais** créé par Learning (AD-2/F-07 : les événements Learning **alimentent** Progress, seul Progress l'émet). Les findings typés (lacune / contradiction / erreur) portent **chacun une provenance corpus** (AD-11 / ADR §17 : les formulations du professeur restent textuellement dominantes ; l'explication d'Aurora est séparée et labelisée — jamais de réécriture créative).
- **Async** : **flux serveur uniquement** — le kernel (Tutor, AD-12) n'est **pas** déployé dans l'app ; l'analyse = job `mirror-analysis` (AD-8, 01 §5.1 `fn-import-course` family, 01 §4.2 G-L3 closed 2026-09-22) ; `killed` possible sur ce flux (AD-13/G-M2). La **saisie** = **locale** (AD-7, SQLite) → disponible offline.
- **Saisie** : `TextArea` (grasse, l'utilisatrice **écrit** son explication, 05 §4.9.2) + `AudioWaveformRenderer` (AD-10, pack 02 §5.5 : la **saisie vocale** — la transcription est indépendante de la lecture audio, doc v1.5, pack 04 §5 : `TranscriptionProvider` optionnel, **accepte l'absence** du provider). Pas de `TextField` ici (pas de saisie courte, pas de QCM type). Pas de `RadioButton` (pas de choix multiples, pas de data table, S3 l.136 interdit ion-list data).
- **Permissions** : micro (capture vocale) = permission-matrix §1 (docs/learning/overview.md §14 : caméra/mic pour capture, optional paths) ; si micro absent → pas de saisie vocale, texte seul (AD-1 : graceful degradation, 01 §6).

## §4 États (matrice complète AD-13 / 05 §3.7 l.1244–1309)

### (a) 6 états S6 par élément async (ui-libraries §6 l.174–187)

- **loading** (le kernel **analyse** : le `Job` est persisté, AD-8 ; durée ~5-15s, serveur AD-12) : Zone résultat = Skeleton (shape final, 05 §3.3) + ProgressRing 48px (05 §3.3) au centre ; tokens = --aurora-skeleton (pulse opacity 0.6→1 / 1.2s, 05 §2.6 règle 4) ; texte exact = « Analyse en cours… » (court, car serveur AD-12) ; CTA = « Lancer l'analyse » reste **actif** mais en `loading` (ProgressRing 16px **dans** le bouton, 05 §3.1) ; **entrée** = fade 200ms easeOut (PAGE_TRANSITION, ssootCode motionRefs motion.tsx @aurora/ui) ; **sortie** = skeleton → contenu partiel crossfade 200ms (pack 02 §7 : si > 300ms, le contenu partiel apparaît en dessous du Skeleton) ; **pas** de layout animation (S5 l.169) ; si `prefers-reduced-motion` → statique (05 §2.6 règle 2) ; si Focus Mode → atténué (05 §2.6 règle 3).
- **empty** (aucune analyse lancée) : zone contenu vide + CTA primaire « Commencer une session Mirror » (CTA actionnable, pack 02 §7 : « jamais un bloc vide ») + `TextArea` disponible (l'état est **actionnable**) ; tokens = --aurora-bg-subtle + --aurora-text-secondary ; **entrée** = fade 200ms ; **sortie** = tap CTA → flux loading (analyse serveur, AD-12) ; si offline → CTA désactivé + explicatif (AD-13 A5 : « les actions qui exigent le cloud sont désactivées avec explicatif »).
- **error** (le kernel a échoué, un provider IA est indisponible, AD-4 → fallback AD-5) : Callout danger (« Analyse impossible : le cloud est indisponible ») + CTA ghost « Réessayer » (re-soumission, AD-13 A4) ; tokens = --aurora-danger / --aurora-danger-surface (frozen 05 §5.1) ; **entrée** = fade 200ms ; **sortie** = retry OK → flux loading, si fail → retry encore (pas de crash) ; **pas** de Callout qui disparaît (AD-7 : l'erreur est affichée, pack 02 §7 : « l'état error est toujours visible, jamais caché »).
- **success** (l'analyse est terminée : les `Callout` (lacunes/erreurs) sont affichés + la **prochaine action** est proposée) : Zone résultat = Callout info (concepts compris) + Callout warning (lacunes : « Vous n'avez pas mentionné [concept clé] ») + Callout danger (erreurs factuelles : « [la formule que vous avez écrite] n'est pas correcte, la bonne est [la formule du corpus] », doc §17) ; chaque Callout pointe vers une fiche §4.7.1 ou un cours §4.7.1.2 ; tokens = --aurora-success / --aurora-success-surface (si tous les concepts sont compris, Callout success) ; **entrée** = fade 200ms ; **sortie** = CTA « Réviser les lacunes détectées » (sortie vers `fiches-liste`, §4.7.1) ou retour arrière (close overlay, retour à la fiche/cours) ; **pas** de CTA manuel pour auto-redirect (invariant AD-14 : l'écran n'est pas un dashboard).
- **offline** (réseau coupé, analyse non disponible : module serveur-only AD-12/F-09) : Badge offline (header) + Callout info (« Hors-ligne — l'analyse sera exécutée à la reconnexion. La saisie est archivée dans le store local. ») ; tokens = --aurora-info (frozen 05 §5.1) + --aurora-warning (badge) ; CTA = « Lancer l'analyse » **désactivé** avec explicatif (pack 02 §7 : « les actions qui exigent le cloud sont désactivées avec explicatif ») ; la `TextArea` reste **actif** (AD-7 : la saisie locale fonctionne) ; **entrée** = fade 200ms ; **sortie** = retour online → re-query (retour au flux loading/success) ; **pas** de CTA d'action (l'analyse n'est pas actionnable offline, 05 §4.9.2).
- **killed** (flux serveur uniquement : relaunch cold après kill système, AD-13/G-M2) : Skeleton + « Reconnexion… » (§4a killed row) : **pas** de CTA, **pas** de retry, **pas** de navigation (ssootCode stateRefs ux-states.tsx killed) ; tokens = --aurora-skeleton (+ --aurora-danger pour le badge d'état) ; **entrée** = fade 200ms ; **sortie** = reconnexion OK → re-query → loading/success ; le contenu **local** (AD-7 : la saisie archivée dans SQLite) reste lisible en dessous (pas de crash, pas de perte de contenu local, 05 l.1294–1301 : « les données du mirror local s'affichent, jamais d'écran blanc ni de reset »).

### (b) États sémantiques §6.1 (ui-libraries l.189–202)

## §6 Tokens (discipline AD-17, 05 §2 l.93–346 + ui-libraries S4 l.145–160)

- **Aucune valeur brute** : pas de hex, pas de px de spacing/typo/radius codé en dur — toujours via variables CSS `hsl(var(--aurora-*))` (05 §5.2/5.3, ssootCode tokenRefs aurora.css).
- **Règle bloquante 05 §5.1 (l.2931)** : le thème ne touche **jamais** success/warning/danger/info (frozen semantic tokens) — les Callout info/warning/danger utilisent **uniquement** les variables, pas de redefinition par thème (05 §5.1 : « Danger reste Danger, quelle que soit la palette du thème »).
- **10 thèmes + 3 presets = comportement par couche** (05 §5.2, ssootCode themeRefs) : pas de valeur par thème (jamais d'override par thème sauf L3 local override = Focus only, OQ-15) ; l'écran ne code **aucune** valeur par thème.
- **focus visible** : le theme owns focus-ring (aurora.json `focusTreatment = ring`, ssootCode a11yRefs) — pas de gestion manuelle du focus par écran.
- **icônes** : 05 §2.5 (l.287) — lucide (ssootCode paginationRefs Chevrons/MoreHorizontal) ; **pas** de custom SVG decoration (S3 l.141 interdit, ssootCode forbidden).
- **coins** : radius ≤ 8px (S3 l.142 interdit > 8px) ; **élévations** = 05 §2.4 (l.254), pas de box-shadow brut.
- **ProgressBar** : toujours déterminée (le temps est estimé, 05 §3.3) — **jamais** `indeterminate` (le glissement = uniquement pour un chargement **réellement** indéterminé, 05 §3.3).
- **typo** : 05 §2.2 (l.190) — Inter (body), JetBrains Mono (valeurs techniques, formules KaTeX) ; **pas** de valeur de typo codée en dur.
