# Écran : cours-liste — Cours (liste)

> Module Learning · Route `/learn` (tab courant, Shell.tsx ; overlay IonModal `/learn/:id` au-dessus du tab, 02 §6.1 S1/S3, router.tsx) · SSoT 05 §4.6.2 l.2521–2563 (doc §2.11, §14) · Statut : détaillé

## §1 Psychologie designer

- **Objectif utilisateur** : voir les cours rattachés (par matière / semestre) et ouvrir un cours pour sa structure et son étude — le cours est **lié** à la Knowledge Base (AD-6 : chaque notion pointe vers sa source ; le `SemanticNode` est la vérité, le cours en est une **vue** agrégée par matière, doc §14 « Vue par domaine », 05 §4.6.2 Objectif).
- **Contexte** : mobile, main libre, réseau patchy probable ; lecture de la liste = **locale** (AD-7 SQLite, rapide), seule action serveur = l'import d'un cours (capture documentaire, doc v1.5, §4.5.2, AD-12) donc différable offline ; ouverture depuis `bibliotheque-ressources` (§4.7.1.1) ou `home` (bloc 5 « Progression critique », §4.1.2) ou les révisions dues (`/learn`, 05 §4.8, app mobile `learn/index.tsx` « due-reviews list + course chain entry »).
- **Fréquence** : sessions de révision, plusieurs fois par semaine ; inventaire de cours = stable (consultation quotidienne possible hors-ligne).
- **État émotionnel cible** : orientation (je vois mes matières/semestres et où j'en suis), confiance (ma bibliothèque locale est là, même offline), motivation (progression visible par cours, CTA d'import actionnable).
- **Erreur la plus probable** : tap d'un cours sans chapitre importé → l'écran détail ouvre en **empty** actionnable (CTA « Importer un cours », 05 §4.6.2 États) ; ou tap du FAB « Importer un cours » en offline → import différé (`Badge info`, pas d'échec).
- **Ce que l'écran RÉSOUT** : inventaire local des cours (lecture AD-7, 100 % offline-capable, _inventory l.107) filtrable par semestre/matière + progression par cours + 2 entrées serveur différables (FAB import + bouton « Organiser » = regroupement par matière, 05 §4.6.2 Zones).

## §2 Contexte fonctionnel

- Entrée : depuis `bibliotheque-ressources` (§4.7.1.1, « entrée depuis cours-liste » l.2507) ou `welcome/home` (bloc 5 « Progression critique », §4.1.2) ou le flux de révisions dues `/learn` (05 §4.8, `learn/index.tsx` header « Apprendre » + data-state=empty « Aucune révision due ») ; sortie : vers `cours-detail` (`/learn/:id`, overlay IonModal, router.tsx) ; retour arrière conserve la sélection (SegmentedControl), store UI pack 02 §3.2, AD-7 persist (05 §4.6.2 Transitions).
- Tab `/learn` (Shell/TabBar, 02 §6.1 S1) : le détail s'ouvre **par-dessus** le tab courant (IonModal/IonSlides, 02 §6.1 S1/S3 detail-over-tab, router.tsx) — pas de navigation destructive.
- Data : cours = **vue agrégée par matière** de la Knowledge Base (AD-6, doc §14) ; la liste, le filtre et la progression = **lecture locale** (AD-7, SSoT _inventory l.107 « offline-capable (mirror local) ») ; le **seul** flux serveur = l'import (capture documentaire §4.5.2 + « Organiser » = regroupement, 05 §4.6.2 Zones) → killed possible sur ce flux uniquement.
- `learning.cours` (feature-registry, _inventory l.107) : **lecture** = offline (miroir local AD-7) ; **import** = online-required (AD-12 : l'agent exige le cloud).

## §4 États (matrice complète AD-13 / 05 §3.7 l.1244–1309)

### (a) 6 états S6 par élément async (ui-libraries §6 l.174–187)

- **loading** (liste locale AD-7 → courte) : `SkeletonListItem` (forme réelle, 05 l.593–597) imitant titre + Badge + ProgressRing xs ; tokens = --aurora-skeleton ; texte = « Cours… » (court, ou aucun) ; CTA = **aucun** (le FAB n'apparaît qu'avec le contenu) ; **entrée** = fade 200ms easeOut (PAGE_TRANSITION, ssootCode motionRefs motion.tsx @aurora/ui) ; **sortie** = skeleton → liste crossfade 200ms ; **si > 300ms**, le contenu partiel apparaît **en dessous** (pack 02 §7, 05 §4.6.2 loading l.2543–2546).
- **empty** (aucun cours importé / aucun cours sur le filtre) : EmptyState (05 l.643–654 : icône domaine 48px + title « Aucun cours importé » + body « Importez un cours pour commencer. ») + CTA primaire « Importer un cours » (actionnable, pack 02 §7, 05 l.2544–2545) ; tokens = --aurora-text-muted/primary/secondary + --aurora-accent-primary ; **entrée** = fade 200ms ; **sortie** = tap CTA → BottomSheet d'import (§4.5.2) → flux loading si online.
- **error** (import/lecture défaillante, cours corrompu) : Callout `danger` (chapitre/cours corrompu signalé, **les autres restent accessibles**, 05 l.2546) + CTA ghost « Réessayer » (règle : un Callout danger **doit** porter une action, 05 l.634–636) ; tokens = --aurora-danger-surface (frozen) ; **entrée** = fade 200ms ; **sortie** = retry OK → success, fail → Callout persiste (pas de crash, AD-7 : le local reste).
- **success** (liste locale chargée, cours consultables) : aucun écran dédié — le contenu = l'état normal (05 §3.7 success = le data state, ui-libraries §6 l.183) ; tokens = sémantiques neutres ; CTA = tap ListItem → `cours-detail` ; **entrée** = crossfade 200ms depuis le skeleton ; **sortie** = navigation overlay.
- **offline** (AD-1, lecture conservée) : Badge offline (header, --aurora-warning) + Badge info « synchronisera à la connexion » sur les cours non synchronisés (05 l.2547–2549, pattern §4.6.1 l.2502–2503) ; tokens = --aurora-info-surface + --aurora-warning (frozen) ; CTA = FAB **désactivé** si cloud (05 §3.7 l.1252) ; **entrée** = fade 200ms ; **sortie** = retour online → resync en arrière-plan (05 l.2547 « synchronisation cloud en arrière-plan ») → success.
- **killed** (relaunch cold, AD-13/G-M2) : skeleton + bannière fine « Reconnexion… » (05 l.1285–1295 : sous-état de `loading`, **jamais** écran blanc, AD-7 : le mirror local s'affiche, auto-resync) ; tokens = --aurora-skeleton + --aurora-danger (bannière) ; CTA = **aucun** (pas de retry, pas de navigation) ; **entrée** = fade 200ms ; **sortie** = resync OK → bannière disparaît → liste locale re-queryée (sortie non animée, ssootCode stateRefs ux-states killed).

## §6 Tokens (discipline AD-17, 05 §2 l.93–346 + ui-libraries S4 l.145–160)

- **Aucune valeur brute** : pas de hex, pas de px de spacing/typo/radius codé en dur — toujours via variables CSS `hsl(var(--aurora-*))` (05 §5.2/5.3, ssootCode tokenRefs aurora.css) ; spacing = `aurora.space.*` (05 l.240), radius = `aurora.radius.md` 8px / `lg` 12px FAB (05 l.261–262), élévation = `aurora.shadow.1/2` (05 l.276–277), typo = Inter + JetBrains Mono (ssootCode themeRefs aurora.css).
- **Règle bloquante 05 §5.1 (l.2931)** : le thème ne touche **jamais** success/warning/danger/info (frozen semantic tokens) — le Callout danger (error row), le Badge offline (warning), le Badge info (différenciation offline) et la bannière killed (danger) consomment ces tokens **sans jamais les redéfinir par thème**.
- **10 thèmes + 3 presets = comportement par couche** (05 §5.2 l.2961, ssootCode themeRefs) : l'écran ne code **aucune** valeur par thème ; pas d'override local (le seul L3 = Focus, OQ-15, ssootCode themeRefs theme-adapter.tsx).
- **focus visible** : le thème owns focus-ring (aurora.json focusTreatment = ring, ssootCode a11yRefs) — pas de gestion manuelle du focus par écran.
- **icônes** : 05 §2.5 l.287 — lucide (battery shadcn) ; **pas** de custom SVG decoration (S3 l.141 interdit).
- **coins** : radius ≤ 8px (S3 l.142 interdit > 8px) ; le FAB = `aurora.radius.lg` (12px, 05 l.262 — spécifique FAB, **pas** une violation globale).
