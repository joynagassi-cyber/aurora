### (d) `killed` sur tout flux serveur (ui-libraries S6 l. 185 ; 05 §3.7 l. 1290-1301)

Le board = **lecture locale 100 %** (AD-7, PowerSync mirror, pack 03 §4.1) — **aucun** flux serveur **synchrone** au mount ; les seuls flux serveurs = la **sync au retour** (pack 03 §5.5 re-sync) et le **scan de documents** (action cloud, pack 04 §3.2.3). `killed` = **sous-état de `loading`** : relaunch cold **part du mirror** (AD-7 — jamais d'écran blanc ni de reset), les cards reviennent en `Skeleton` jusqu'au resync, bannière fine **« Reconnexion… »** (l. 1296 ; ui-libraries S6 l. 185 : « Skeleton + auto-resync »). Les composants `loading = n/a` (`FAB`, `Menu`, `BottomSheet`) n'ont **rien** de nouveau à rendre (l. 1297-1298).

## 8. Pagination

- **Règle unique nommée** : le board = **5 colonnes** (1 par statut, 05 §4.3.3 l. 1579-1580 ; OQ-2 WDS close : les 5 colonnes restent **toutes** visibles sur 540 px, le SSoT = 5 statuts ADR §2.2, pas de repli).
- **Scroll horizontal** de la rangée (mobile) ; **scroll vertical** par colonne (05 §4.3.3 l. 1581).
- **Pas de `shadcn Pagination`** (ui-libraries S1 l. 37) : ce n'est pas une liste paginée, c'est un board scrollable (la Pagination est pour les `Table` paginées, pas pour le board).
- **Volume > 100 tasks** par colonne : **Virtuoso** (`react-virtuoso`, ui-libraries S1 l. 63, fallback OQ-09) ou AG Grid Community virtualisé (ui-libraries S1 l. 20, S5 l. 167 : `rowBuffer: 10`, `maxVisibleRows: 30`, 60 fps Pixel 4a) — le volume réel des colonnes (cas Horeb : tâches nocturnes, volume modéré) **ne dépasse pas 100** en cas courant ; **OQ-4** du présent doc : le SSoT ne tranche pas la virtualisation par colonne.
- **Le tri** (filtre par projet/priorité/matière, 05 §4.3.3 l. 1576-1578) est **persisté** par écran (store UI pack 02 §3.2 — le retour sur le board retrouve le filtre d'avant, règle de non-surprise).

## 10. Thèmes

Comportement des 3 couches sur le board Kanban (05 §5 l. 2925-3307 ; overview §3 l. 27-54) :

- **Couche 1 — Style neutre** (Light `#FFFFFF` / Dark `#121212`) : fournit `surface`, `surface-alt`/`bg-subtle` (fond des `KanbanColumn`), `text-primary/secondary`, `border`, `shadow` — les tokens **géométriques et sémantiques** (fond, texte, bordures des colonnes). Dark = **première classe** (`#121212` plain dark, pas `#000` — overview §2 l. 17-23 ; WDS 05.4 OQ-16 : Nocturne = thème par défaut pour la cible nocturne).
- **Couche 2 — Thème expressif** (10 thèmes vivants : Aurora par défaut, Lagoon, Boreal, Sakura, Vesper, Solara, Terra, Verdant, Citrus, Cosmos — 05 §5.4 l. 3010-3046) : fournit `accent.primary/secondary` — les tokens **couleur** (le FAB = `primary`, la `ProgressBar` = `primary`, les `Badge` de statut = `primary-surface`/`success-surface`). **Règle bloquante §5.1** (05 l. 2931-2959) : un thème **ne redéfinit JAMAIS** `success`/`warning`/`danger`/`info` — le `Badge danger` « à resync » (état `error`) et le `Badge info` `Offline` (TopBar) sont **thème-indépendants** (neutral layer).
- **Couche 3 — Presets** (Slate / Nocturne / High Contrast, 05 §5.5 l. 3153-3165) : Nocturne = désaturation (le board reste **identique** en structure, les teintes passent en métallique) ; High Contrast = `7:1 contrast`, `56px targets`, `3px focus ring` (overview §3 l. 45-49) — les `KanbanCard` (≥ 56px) et le FAB (56px) restent **identiques** (ajustement, pas de nouveau composant).
- **Local adaptation V1** = Focus Mode **uniquement** (OQ-15, 05 §5.2 l. 2961-2990) : le Focus Mode **bloque** le board (l'écran est masqué pendant une session Focus, WDS 05.4 §5 : « si Horeb est en focus, `/kanban` est masqué ») ; les toasts sont **différés** (jamais pendant un pomodoro, 05 §3.5 l. 835-837).
- **Résolution** : `valeur = theme_accent[token] ?? style_neutre[token] ?? défaut` (05 §5.3 l. 2992-3008) — changée par `resolveToken` + `<AuroraThemeProvider>` (JSON dans `packages/ui/src/themes/`, **jamais** de changement silencieux au foreground, 05 §5.8 l. 3235-3279).
