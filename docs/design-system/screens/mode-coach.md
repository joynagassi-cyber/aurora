# Écran : mode-coach — Mode coach (Learning)

> Module Learning · Route `/coach` (enveloppe overlay IonModal, 02 §6.1 S1/S3, router.tsx pattern ; cf. `_inventory.md` #37) · SSoT 05 §4.9.1 l.2760–2839 + WDS 04.4 · Statut : détaillé
> Classe offline (catalog `learning.coach`) : **PARTIAL** — check-ins cadence user-controlled + OneSignal server + local (05 §4.9.1 : kernel = serveur, AD-12/F-09 ; coaching = désactivé offline)

## §1 Psychologie designer

- **Objectif utilisateur** : répondre à un **coaching adaptatif** de l'agent (doc §13 « Aurora Coach — accompagnement personnel adaptatif ») : l'agent **initie** de courtes interactions (check-ins contextuels : début de journée, avant un bloc important, après une session, fin de journée) pour **suivre** la discipline, **comprendre** les écarts plan/réalité, et **adapter** la journée (replanification dynamique, doc §13.1) — le coaching **n'est pas** un chat libre (05 §4.9.1 : « privilégier la pertinence contextuelle, respecter les périodes de silence et pouvoir être désactivé ou ajusté »).
- **Contexte** : mobile, main libre ; le fil est court (check-ins du jour) ; le kernel tourne **côté serveur** (AD-12/F-09, 02 §6.4) → écran dépend du réseau ; ouverture depuis `welcome/home` (bloc 7 « Suggestions pertinentes d'Aurora Coach », §4.1.2) ou depuis `focus-mode` (après session, §4.4.2).
- **Fréquence** : plusieurs check-ins par jour (cadence définie par l'utilisatrice : horaires de silence + niveau d'intervention, ADR §13), consultation du fil = lecture courte (pas de longue session).
- **État émotionnel cible** : encadrement sans intrusion (le coach **propose**, n'impose pas, 05 §4.9.1), clarté (constat explicite, action lisible), apaisement (pas de « notification multiplier », doc §13.1), respect (horaires de silence honorés, ADR §13).
- **Erreur la plus probable** : confondre l'écran avec un chat libre (saisir de longues demandes) alors que le `TextField` = saisie libre **optionnelle** contextuelle (05 §4.9.1 : « le coaching est contextuel, pas un chat ») ; ou attendre un check-in pendant une **horaires de silence** (l'état `empty` est **normal**, pas une erreur, §4b).
- **Ce que l'écran RÉSOUT** : fil court de check-ins + constats (Callout info/warning/success) + actions proposées (Button primary/ghost) + saisie libre optionnelle + contrôle utilisateur (désactiver aujourd'hui / réglages), avec état kernel visible (Badge `AgentRunState`) et 4 états réseau (loading/empty/error/offline, §4).

## §2 Contexte fonctionnel

- **Entrées** : `welcome/home` bloc 7 (§4.1.2) ; `focus-mode` après session (§4.4.2, bilan contextuel) ; deep-link OneSignal « coach check-in » (02 §6.1 Agent row : push → `/agent`, ici `/coach` — cf. §14 OQ-01) ; **Sorties** : `progress-dashboard` (§4.5.2, le coaching **alimente** le dashboard, doc §13) ; `settings` (§4.6.1, réglages du coaching : cadence, silence, intervention, ADR §13) ; retour arrière **conserve** le fil (store UI pack 02 §3.2, AD-7 persist).
- **Async** : **flux serveur uniquement** — le kernel (Planner/Coach/Tutor/Researcher/Executor, AD-12) n'est **pas** déployé dans l'app (02 §6.4 : l'app **consomme** la surface UI du kernel, `AgentRunState` typée : `idle/planning/retrieving/acting/done/error`) ; pas d'éxecution locale (règle 1 du §2.6 : scientific data jamais animée — ici **aucun** renderer AD-10, cf. §11).
- **Permissions** : le coaching respecte **user_context** (pack 01 §4 Identity : cadence, horaires de silence, niveau d'intervention, ADR §13) ; **OneSignal** (04 §3.2.5, clé serveur uniquement) : les notifications de check-in sont **servirées**, l'écran lui-même = pas de notification locale (classe PARTIAL, catalog §29).
- **Feature disabled** : si `learning.coach` est désactivé par feature-registry (G-M7 NEEDS_DECISION, cf. `_inventory.md` #37) → l'écran rend `data-state=feature-disabled` + CTA re-enable (ssootCode stateRefs not-found/index.tsx, **jamais** un crash/404 brut).

## §4 États (matrice complète AD-13 / 05 §3.7 l.1244–1309)

### (a) 6 états S6 par élément async (ui-libraries §6 l.174–187)

## §6 Tokens (discipline AD-17, 05 §2 l.93–346 + ui-libraries S4 l.145–160)

- **Aucune valeur brute** : pas de hex, pas de px de spacing/typo/radius codé en dur — toujours via variables CSS `hsl(var(--aurora-*))` (05 §5.2/5.3, ssootCode tokenRefs aurora.css).
- **Règle bloquante 05 §5.1 (l.2931)** : le thème ne touche **jamais** success/warning/danger/info (frozen semantic tokens) — utiliser uniquement via les variables, pas de redefinition par thème.
- **10 thèmes + 3 presets = comportement par couche** (05 §5.2, ssootCode themeRefs) : pas de valeur par thème (jamais d'override par thème sauf L3 local override = Focus only, OQ-15) ; l'écran ne code **aucune** valeur par thème.
- **focus visible** : le theme owns focus-ring (aurora.json focusTreatment = ring, ssootCode a11yRefs) — pas de gestion manuelle du focus par écran.
- **icônes** : 05 §2.5 (l.287) — lucide (ssootCode paginationRefs Chevrons/MoreHorizontal) ; **pas** de custom SVG decoration (S3 l.141 interdit, ssootCode forbidden).
- **coins** : radius ≤ 8px (S3 l.142 interdit > 8px) ; **élévations** = 05 §2.4 (l.254), pas de box-shadow brut.
