> Module Knowledge · Route `/knowledge` (02 S6.1 p.10, router.tsx l.69) · SSoT : docs/knowledge/overview.md §1/§4/§5/§9/§16/§17 · Statut : claimé (SSoT écran = docs/knowledge/overview.md, pas de section 05 §4.x dédiée — OQ ci-dessous si section attendue)

## §1 Psychologie designer

- **Objectif utilisateur** : naviguer la hiérarchie du savoir (domaines → chapitres → concepts) en exploration progressive (niveau 1 au mount, sous-niveaux lazy — 02 §9.2 R1, docs/knowledge/overview §4 « browse tree »), comprendre l'état de maîtrise global (couleurs figées `node-mastered`/`fragile`/`forgotten`, 05 §3.6.6 l.976–982), identifier les branches à consolider (Oubliés) ou à approfondir (Fragiles) et percer vers un nœud détail (tap → `/knowledge/:nodeId`, SemanticTreeRenderer.tsx:257–262).
- **Contexte** : mobile, main libre, réseau patchy ; accès depuis un onglet du Home (non dans les 5 figés, 05 §3.4 l.677–680 — OQ-01) ou deep link `/knowledge` (router.tsx:108) ; l'arbre reste 100 % interactif offline (pan/zoom/repli, lecture SQLite AD-7, docs/knowledge/overview §16) → consultation hors-ligne totale ; la **retrieval sémantique** (nouveaux nœuds) = serveur-only (AD-12/F-09, docs/knowledge/overview §11).
- **Fréquence** : à chaque session d'orientation (avant/n'après étude) — plusieurs fois par semaine ; l'arbre s'affiche vite (racine + niv. 1 au mount, 02 §9.2 R1), les branches profondes se chargent à la demande (lazyChildren, SemanticTreeRenderer.tsx:203–211).
- **État émotionnel cible** : orientation (je vois ma matière hiérarchisée, pas un nuage de points chaotiques — règle de lisibilité ADR §14, docs/knowledge/overview §1), calme (pas de sur-charge : le +/− se trouve **dans** le nœud, pas en overlay flottant, 05 §3.6.6 l.983–990), confiance (provenance traçable, AD-11 — chaque nœud lié puce sa `SourceRef`).
- **Erreur la plus probable** : l'utilisateur **panne/zoom** et perd le fil (l'arbre défile, on ne sait plus où l'on est) → le `fitView` (prop par défaut true, SemanticTreeRenderer.tsx:274) récenter ; ou un **sous-arbre non syncé** alors que le réseau est coupé → `Badge info` « à synchroniser » sur les nœuds concernés (05 §3.6.6 l.997–1000), jamais de nœud **inventé** (le loading n'est que pour le sous-arbre en cours, jamais l'arbre entier, 05 §3.6.6 l.1000).
- **Ce que l'écran RÉSOUT** : une **vision hiérarchique lisible** du savoir (pas un graphe chaotique, ADR §14 « readable hierarchy, not a second-brain web ») avec état de maîtrise global (couleurs sémantiques figées, 05 §2.1.2/2.1.3), navigation contextuelle (branches dépliables), et point d'entrée vers le détail (tap nœud → `/knowledge/:nodeId`, context-preserving 02 S6.2). La vérité = Knowledge (AD-6, docs/knowledge/overview §2) ; l'écran **n'écrit rien** dans `semantic_*` ni `NodeState` (AD-2/F-02, docs/knowledge/overview §24 : l'agent *request*, ne write jamais la structure).

## §2 Contexte fonctionnel

- **Entrée** : tab (5ᵉ ? — OQ-01) ou deep link `/knowledge` (router.tsx:108) ; sortie vers `/knowledge/:nodeId` (tap nœud, `onSelectNode` — SemanticTreeRenderer.tsx:257–262, overlay IonModal 02 §6.1 S1/S3 detail-over-tab, router.tsx l.69–70).
- **Data** : `SemanticNode` (kind ∈ principle/domain/subject/concept/law/formula/method/example/application/skill ; label/summary, supabase/migrations/0004_knowledge.sql:43–61) + `SemanticEdge` (relation ∈ depends_on/is_a_case_of/deepens/applies/leads_to, 0004:63–75) + `SemanticBridge` (ponts inter-domaines, secondaires, on-demand, 0004:77–85) + `NodeState` (state ∈ collapsed/expanded/selected/focused/mastered/fragile/forgotten, 0004:91–103) — consommés depuis `@aurora/domain` (AD-15, 02 §5.1 l.287–288), **jamais** redéfinis par l'écran.
- **Async** :
  - **Lecture locale** = miroir SQLite (AD-7, docs/knowledge/overview §16 : « root + level-1 first, deeper branches lazy ») → rapide, pas de skeleton si cache chaud.
  - **Retrieval sémantique** (nouveaux nœuds, embedding) = **serveur-only** (AD-12/F-09, docs/knowledge/overview §11 : « device never runs semantic retrieval locally ») → **killed possible** sur ce flux **uniquement** (l'arbre local reste 100 % interactif pendant le killed, AD-7).
  - **Bridges** (ponts inter-domaines) = on-demand (05 §3.6.6 « Phased Layering : the app toggles the layer on/off » — SemanticTreeRenderer.tsx:128–134 dashed edges).
- **État de sélection** : l'écran **lit** `NodeState.selected/focused` (docs/knowledge/overview §2 : Knowledge est the sole writer, AD-6) ; l'écran **n'écrit JAMAIS** `NodeState` ni `semantic_*` (AD-2/F-02, docs/knowledge/overview §24 : inspect/link/explain = read-only). L'état d'expansion des branches est persisté dans le `ui-state` store (`knowledgeExpanded`, knowledge/index.tsx:20).
