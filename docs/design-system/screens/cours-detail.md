# Écran : cours-detail — Cours (détail)

> Module Learning · Route `/learn/:id` (overlay IonModal sur le tab courant, 02 §6.1 S1/S3, router.tsx) · SSoT 05 §4.6.2 l.2521–2563 + WDS 03.6 · Statut : détaillé

## §1 Psychologie designer

- **Objectif utilisateur** : voir la structure d'un cours rattaché (chapitres, concepts, définitions, formules, méthodes, exercices) — le cours est **une vue agrégée par matière** de la Knowledge Base (AD-6, 05 §4.6.2), pas l'arbre sémantique lui-même — et lancer l'étude (QCM §4.8.2 ou fiche §4.7.1).
- **Contexte** : mobile, main libre, réseau patchy probable ; lecture = locale (SQLite AD-7, rapide), génération de QCM/sheets = serveur (AD-12) donc dépend du réseau ; ouverture depuis bibliotheque ou home (bloc 5), overlay = l'utilisateur reste dans son flux.
- **Fréquence** : sessions de révision, plusieurs fois par semaine ; contenu local (AD-7) donc consultation possible hors-ligne.
- **État émotionnel cible** : orientation (je vois la structure de ma matière), confiance (mon contenu est dispo, même offline), motivation (CTA « Commencer l'étude » visible).
- **Erreur la plus probable** : tap sur un concept → attend sa fiche (§4.7.1) mais le concept pointe vers une fiche non générée (état empty par concept, 05 §4.6.2 empty = cours sans chapitre importé, CTA actionnable).
- **Ce que l'écran RÉSOUT** : vue hiérarchique d'une matière (chapitres dépliables + concepts + formules KaTeX) + 2 sorties d'étude (QCM / fiches), avec progression et état de mastery visibles, lecture 100 % locale (AD-7).

## §2 Contexte fonctionnel

- Entrée : depuis `bibliotheque-ressources` (§4.7.1.1) ou `welcome/home` (bloc 5 « Progression critique », §4.1.2) ; sortie : vers `fiches-liste` (étudier une fiche du cours) ou `qcm` (§4.8.2, tester la compréhension) ; retour arrière conserve le chapitre ouvert (store UI pack 02 §3.2, AD-7 persist) (05 §4.6.2 Transitions).
- Overlay IonModal `/learn/:id` (router.tsx detail-over-tab rule 02 §6.1 S1/S3) : le tab courant reste sous l'overlay (pas de navigation destructive).
- Data : cours = **vue agrégée par matière** de la Knowledge Base (AD-6) ; `SemanticNode` = la vérité, le cours en est une vue (doc §14 « Vue par domaine ») ; chaque notion pointe vers sa source (§4.6.2 Objectif).
- Async : lecture **locale** (SQLite AD-7) → Skeleton court (« un Skeleton qui dure > 300ms doit laisser apparaître le contenu partiellement en dessous », pack 02 §7) ; QCM/génération sheets = **serveur** (AD-12/F-09, Agent kernel `Plan → Retrieve → Tools → Verify`, §4.8.2) → killed possible sur ce flux uniquement.
- Chapitres corrompus : le `SemanticNode` est signalé (Callout danger, 05 §3.6.4 pattern), les autres restent accessibles (§4.6.2 error).

## §4 États (matrice complète AD-13 / 05 §3.7 l.1244–1309)

### (a) 6 états S6 par élément async (ui-libraries §6 l.174–187)

- **loading** (flux lecture local + flux QCM serveur) : Skeleton liste chapitres + ProgressRing (§3, loading row) ; tokens = --aurora-skeleton ; texte exact = « Chargement du cours… » (court, car local AD-7) ; CTA = aucun (pas d'actions avant données) ; **entrée** = fade 200ms easeOut (PAGE_TRANSITION, ssootCode motionRefs motion.tsx @aurora/ui) ; **sortie** = skeleton → contenu partiel crossfade 200ms (pack 02 §7 : si > 300ms le contenu apparaît partiellement en dessous du Skeleton).
- **empty** (cours sans chapitre importé) : zone contenu vide + CTA primaire « Importer un cours » (capture documentaire, 05 §4.6.2 empty) ; tokens = --aurora-bg-subtle + --aurora-text-secondary ; **entrée** = fade 200ms ; **sortie** = import lancé → CTA disparaît, liste apparaît (transfert au flux loading).
- **error** (chapitre corrompu ; le cours reste ouvert) : Callout danger (§3, Callout row) signalant le `SemanticNode` corrompu ; les autres chapitres restent accessibles (§4.6.2 error) ; tokens = --aurora-danger / --aurora-danger-surface ; CTA = « Réessayer » (re-load local) ; **entrée** = fade 200ms ; **sortie** = retry OK → chapitre rechargé, Callout disparaît.
- **success** (génération QCM OK, retour sur l'écran) : Toast success (§3, QCM/fiches row) ; tokens = --aurora-success ; texte = « QCM généré — prête à commencer » ; CTA = le CTA principal « Commencer l'étude » redevient actif ; **entrée** = toast slide up 200ms (translateY, pas de layout, S5 l.169) ; **sortie** = auto-dismiss 3s (§3.5 l.823 pattern).
- **offline** (lecture OK, import/serveur KO) : Badge offline (§3, offline row) + Badge info « synchronisera à la connexion » sur les éléments différés (§4.6.2 offline) ; tokens = --aurora-warning + --aurora-info ; CTA = import/qcm désactivés (pas de CTA serveur) ; **entrée** = fade 200ms ; **sortie** = retour online → refetch (retour au flux loading/success).
- **killed** (flux serveur QCM seulement, AD-13/G-M2) : Skeleton + « Reconnexion… » (§3, killed row) ; tokens = --aurora-skeleton + --aurora-danger ; CTA = **aucun** (pas de retry, pas de navigation, ssootCode stateRefs ux-states) ; **entrée** = fade 200ms ; **sortie** = reconnexion OK → re-query → loading/success ; le contenu **local** du cours (chapitres déjà importés) reste lisible en dessous (AD-7), seul le flux serveur est mort.

### (b) États sémantiques §6.1 (ui-libraries l.189–202)

- **en-cours** (chapitre ouvert, étude lancée mais QCM non terminé) : ring node = `warning/50` (Fragile pattern, ssootCode stateRefs) + ProgressRing partielle (05 §3.6) ; tokens = --aurora-warning ; CTA = CTA principal reste actif (reprendre) ; source = 05 §3.6 node states + ui-libraries §6.1 l.197.
- **terminé** (QCM validé, chapitre maîtrisé) : ring node = `success/50` (mastered, ssootCode SemanticTreeRenderer mapping) ; tokens = --aurora-success ; CTA = « Réviser les fiches des erreurs » (sortie §4.8.2, si erreurs) ; source = ui-libraries §6.1 l.198 + 05 §3.6.6.
- **échec** (QCM échoué, notion fragile/oubliée) : ring node = `danger/50` (forgotten/fragile, ssootCode stateRefs) + Callout warning « Correction : [bonne réponse] » avec explication **séparée** de la correction (AD-11, §4.8.2) ; tokens = --aurora-danger / --aurora-warning ; CTA = « Relancer le QCM » (regénéré depuis le cours, §4.8.2) ; source = ui-libraries §6.1 l.199 + 05 §4.8.2.

## §6 Tokens (discipline AD-17, 05 §2 l.93–346 + ui-libraries S4 l.145–160)

- **Aucune valeur brute** : pas de hex, pas de px de spacing/typo/radius codé en dur — toujours via variables CSS `hsl(var(--aurora-*))` (05 §5.2/5.3, ssootCode tokenRefs aurora.css).
- **Règle bloquante 05 §5.1 (l.2931)** : le thème ne touche **jamais** success/warning/danger/info (frozen semantic tokens) — utiliser uniquement via les variables, pas de redefinition par thème.
- **10 thèmes + 3 presets = comportement par couche** (05 §5.2, ssootCode themeRefs) : pas de valeur par thème (jamais d'override par thème sauf L3 local override = Focus only, OQ-15) ; l'écran ne code **aucune** valeur par thème.
- **focus visible** : le theme owns focus-ring (aurora.json focusTreatment = ring, ssootCode a11yRefs) — pas de gestion manuelle du focus par écran.
- **icônes** : 05 §2.5 (l.287) — lucide (ssootCode paginationRefs Chevrons/MoreHorizontal) ; **pas** de custom SVG decoration (S3 l.141 interdit, ssootCode forbidden).
- **coins** : radius ≤ 8px (S3 l.142 interdit > 8px) ; **élévations** = 05 §2.4 (l.254), pas de box-shadow brut.

## §8 Pagination

- **Règle unique nommée : shadcn Pagination** (ui-libraries S1 l.37) — **paramètres** : pas de pagination par défaut pour le cours (une matière = contenu structuré, pas de liste > 100 lignes dans l'écran lui-même).
- Si QCM généré depuis le cours > 100 questions (cas rare, §4.8.2) → **AG Grid virtualisé** via `packages/ui AgGridTable` (60fps Pixel 4a, ssootCode paginationRefs progress/index.tsx) ; si 20–100 questions → **shadcn Pagination** (20–100 = + pagination, ui-libraries S8 l.304–307) ; si < 20 → Table shadcn sans pagination (même décision tree S8).
- **JAMAIS** : AG Grid shadcn Pagination Pager jour/semaine/mois (05 §3.4) sur ce flux (pas de calendrier dans l'écran) ; **pas** de 2 lib sur le même écran (S8 l.333 interdit, ssootCode forbidden).

## §9 Surfaces flottantes (05 §3.5 l.752–865)

- **Modal** = l'overlay IonModal lui-même (§2, router.tsx) ; **pas** de Modal imbriquée dans l'overlay (pas de double floating surface).
- **Toast/Snackbar** (05 §3.5 l.823) : feedback QCM success/error (§4a success) ; **pas** de BottomSheet ni Drawer dans l'écran (pas d'édit de cours ici, le cours = lecture seule, AD-6 vue agrégée).
- **Menu / Dropdown / Popover** : import = Popover shadcn (§3, empty row, S3 l.138 pattern) ; **pas** de Menu contextuel par long-press (pas spec, OQ-02 §14).
- Règle S8 l.333 : **ne jamais mélanger 2 libs sur le même écran** — toutes les surfaces = shadcn/Radix (ui-libraries S1 l.13–14), **pas** de MUI/Ant/Chakra (S3 l.139 interdit).

## §10 Focus Mode (05 §2.6 règle 3, ssootCode forbidden)

- `[data-focus-mode=true]` → attenuated animations (pas de pulse skeleton, ssootCode forbidden : `[data-focus-mode=true] .animate-pulse-skeleton = animation:none`) ; deferred toasts (pas d'interruption) ; contenu inchangé (pas de data change, pas de re-layout, S5 l.169 GPU only) ; pas de CTA modifié (le CTA principal reste actif mais visuellement atténué, OQ-05 §14 si spec manquante).

## §11 Data / contrats (AD-10/AD-12, ssootCode componentRefs)

- **MathBlock** = MathRenderer (katex) figé derrière contrats (packages/ui MathRenderer + contracts.ts ; apps consomment les contrats, **jamais** le moteur, ssootCode componentRefs) ; **pas** d'import direct de katex dans l'écran.
- **SemanticTreeNode compact** = node card (8px radius, ssootCode floatingSurfaces dashboard.tsx pattern « feature nodes = the ONLY card-like surface (8px radius) ») ; ring = NodeState mapping (mastered=success/50, fragile=warning/50, forgotten=danger/50, not-yet=border, ssootCode stateRefs SemanticTreeRenderer) ; **pas** de full React Flow/Dagre dans cet écran (arbre dédié = `arbre-semantique` §4.7.1.3, 05 §4.6.2 Objectif).
- **Data QCM** = `ProgressEvidence` (doc §18.3, 05 §4.8.2) ; l'écran **n'émet jamais** `ProgressEvidenceCreated` (AD-2/F-07 : seul Progress l'émet, les événements Learning **alimentent** le QCM) ; pas de write direct dans l'écran (lecture seule).
- **Local SQLite (AD-7)** : cours = miroir local (mémo §12) ; **pas** de cache par design pour les QCM (génération serveur, AD-12/F-09, §4.8.2 « le QCM n'est pas disponible hors-ligne, l'exécution locale des QCM n'est pas supportée »).

## §12 Offline (classe AD-1/AD-7/AD-12)

- **Classe offline** : **master-feature-catalog** (Learning = feature master, pas optionnelle ; ssootCode stateRefs asciend/index.tsx offline badge via useOnlineStatus) → **miroir local (AD-7/AD-12)** : cours = SQLite (contenu local, 05 §4.6.2 offline = « le cours est consultable (AD-7 local : SQLite, pas de dépendance cloud) »).
- **Dégradation AD-1** : offline → Badge offline (header) + Badge info « synchronisera à la connexion » sur les éléments non synchronisés (§4.6.2 offline) ; l'import d'un nouveau cours et la génération QCM sont **différés** (pas de crash, pas de CTA serveur) ; le contenu local reste 100 % lisible (pas de perte, pas de cache manquant).
