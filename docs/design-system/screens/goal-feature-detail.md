## 10. Thèmes

Le Dark est **première classe** (`#0A0E1A` blue-tinted near-black, pas `#000` — overview §2 l. 17-23).
- **Couche 2 — Thème expressif** (10 thèmes vivants : Aurora par défaut + 9, 05 §5.4 l. 3010-3046) : fournit `accent.primary/secondary` — les tokens **couleur** de l'écran (le `Badge` de sous-état `active` = `accent.primary` ; le `Breadcrumb` segment actif = `accent.selected-surface`). **Règle bloquante §5.1** (05 l. 2931-2959 ; overview §3 l. 39-43) : un thème **ne redéfinit JAMAIS** `success`/`warning`/`danger`/`info` — le `Badge danger-surface` (`blocked`) et le `Badge success-surface` (`done`) sont **thème-indépendants** (neutral layer).
- **Couche 3 — Presets** (Slate / Nocturne / High Contrast, 05 §5.5 l. 3153-3165) : High Contrast = `7:1 contrast`, `56px targets`, `3px focus ring` (overview §3 l. 45-49 ; 05 §6.3 l. 3327-3335) — le `Breadcrumb` (44px) passe en `56px tap target` (ajustement, pas de nouveau composant — 05 §6.3 l. 3330-3331) ; Nocturne = désaturation (les 10 expressifs restent, le preset est appliqué **au-dessus**, 05 §5.8 resolve.ts).
- **Local adaptation V1** = Focus Mode **uniquement** (OQ-15, 05 §5.2 l. 2961-2990) — si l'écran est ouvert **pendant** une Focus session : les nodes secondaires du dashboard parent sont atténués (40 % opacity, goal-dashboard-ui S4 l. 243 : OQ-15) ; sur cet écran, le `KeyValueList` de sous-état **n'est pas** atténué (l'écran = le **point de descente**, pas un fond — le Focus Mode n'applique pas ici, 05 §5.2 l. 2961-2990).
- **Résolution** : `valeur = theme_accent[token] ?? style_neutre[token] ?? défaut` (05 §5.3 l. 2992-3008) — changée par `resolveToken` + `<AuroraThemeProvider>` (JSON dans `packages/ui/src/themes/`, **jamais** de changement silencieux au foreground, 05 §5.8 l. 3235-3250).
