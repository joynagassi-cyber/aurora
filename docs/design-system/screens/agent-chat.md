Status: SPECIFIED (OQ: 6) · Module : Agent · Route : `/agent` · SSoT : docs/agent/kernel.md §13 + ui-libraries §6/§6.1/§9/§9.3/§9.3.1 + 05 §4.9.1 (mode-coach SSoT) + 05 §3.7 (matrice états AD-13)

## 1. Psychologie designer

| Champ | Valeur | SSoT |
|---|---|---|
| Objectif utilisateur | Entrer une intention naturelle, voir l'agent planifier + exécuter + confirmer, et suivre le résultat en streaming | kernel §13 (NL → action pipeline) ; 05 §4.9.1 l. 2765-2777 |
| Contexte | Device mobile (Phase 1) ; moment = l'utilisateur **choisit** de parler à l'agent (jamais un check-in intrusif : horaires de silence respectés, ADR §13) ; réseau = **obligatoire** (le kernel est **serveur**, AD-12/F-09 — jamais d'exécution locale) | kernel §2 ; 05 §4.9.1 l. 2817-2819 |
| Fréquence | **Rare à modéré** : une intention = 1 run (complexe multi-steps) ; le coaching contextuel (check-ins) arrive de l'extérieur (OneSignal deep-link → `/agent`) et n'est **jamais** déclenché par l'utilisateur en boucle | kernel §13 ; 05 §4.9.1 l. 2765-2770 |
| État émotionnel cible | **Confiance + calme** : l'utilisateur voit l'agent **réfléchir** (organisme organique, pas un spinner), puis **agir** (tool-calls, confirmations) ; le résultat arrive en streaming ; l'erreur est **transparente** (reason + fallback, AD-5), jamais silencieuse | kernel §8 (AD-5 traceability) ; ui-libraries §9.3 l. 420-425 |
| Erreur la plus probable | L'utilisateur **croit que l'agent a échoué** alors que le run est en cours (streaming long, multi-steps) — le `Badge AgentRunState` (05 §4.9.1 l. 2781-2784) + le `AgentThinkingLoader` (ui-libraries §9.3) dissipent cette ambiguïté ; l'autre erreur = l'utilisateur **confirme une action destructive** sans lire le scope (le `Confirmation Engine` bloque, kernel §12 l. 132) | 05 §4.9.1 l. 2781-2784 ; kernel §12 l. 132 |
| Ce que l'écran RÉSOUT | « L'agent a-t-il compris mon intention ? » → un plan exécuté, des confirmations explicites, un résultat normalisé + provenance (AD-11) — **pas** un chat libre (05 §4.9.1 l. 2772-2777 : « le coaching n'est pas un chat libre ») | kernel §13 ; 05 §4.9.1 l. 2772-2777 |
| Invariant bloquant | Le kernel **n'importe jamais React** (kernel §15 : « the kernel never touches React components ») — l'écran ne consomme que `AgentRunState` (F-09) ; le `Confirmation Engine` est **bloqueur** (jamais d'action destructive sans confirmation, ADR §5) | kernel §15 l. 234-237 ; kernel §12 l. 132 |

## 2. Zones

Composition **fixe** (05 §4.9.1 l. 2779-2804 + kernel §13) :

- **header** : `TopBar` « Aurora » (IonTitle, Shell.tsx l. 17) + **1 `Badge`** `AgentRunState` (05 §4.9.1 l. 2781-2784 : `thinking` / `idle` / `exiting`, `JetBrains Mono` `xs` **statique** §2.6) — le badge est le **seul** indicateur d'état du kernel dans le header ; **pas** de `back` (écran de tab, règle AD-14 05 §3.4 l. 667-670) ; 2 `IconButton` (historique des runs, menu)
- **content** : la **conversation** — un fil de messages (05 §4.9.1 l. 2786-2790) :
  1. `ListItem` (message utilisateur, `md`, pastille temps `sm` `text-muted`)
  2. `ListItem` (réponse agent, `md`, **streaming** — le `AgentThinkingLoader` (ui-libraries §9.3) remplace le message vide pendant la réflexion ; le texte arrive **en streaming** (en-cours, §6.1 l. 197))
  3. `Callout` (constat : `info` = neutre, `warning` = écart, `success` = alignement — 05 §4.9.1 l. 2787-2790)
  4. **Tool-call card** (`Card` + `Badge` scope `read`/`write`/`destructive` + `Button` « Exécuter » / « Annuler ») — le `Confirmation Engine` (kernel §12 l. 132) ; `destructive` = **obligatoirement** confirmé par `Modal` (05 §3.1 l. 381)
  5. `AgentThinkingLoader` (ui-libraries §9.3) — l'organisme **entre** le message utilisateur et la réponse agent ; l'état `exiting` (200ms collapse+fade) **déclenche** le streaming du texte
  6. **Suggestion natural language** (05 §4.9.1 l. 2790 : « les suggestions sont en **langage naturel**, pas un message système ») — `Button ghost` dans le fil
  7. `TextField` (saisie libre, **optionnelle** — le coaching est contextuel, pas un chat, 05 §4.9.1 l. 2772-2777) — en bas, au-dessus du footer
- **footer** : `BottomNav` (5 items figés : Accueil / Tâches / Apprendre / Progression / Coach — 05 §3.4 l. 670-688) ; le tab **Coach** est **actif** (le /agent = le coach, 05 §4.9.1)
- **surfaces flottantes** : `Modal` de confirmation destructive (kernel §12 l. 132, 05 §3.1 l. 381) ; `Toast` (succès run, S6 l. 183) ; `BottomSheet` historique des runs (AD-7 local, kernel §7 l. 83-84) ; **pas** de `FAB` (AD-14 : le /agent est un écran de conversation, pas de création — le FAB vit dans inbox/tâches/fiches, 05 §3.1 l. 406-408)

## 4. États (5 + killed) — par élément async

**Règle** (ui-libraries §6 l. 174-187 : 6 états S6 ; 05 §3.7 l. 1244-1309 matrice AD-13) : **tout** composant async **expose** les 5 états S6 (`loading`/`empty`/`error`/`success`/`offline`) + `killed` (G-M2, 05 §3.7 l. 1294-1300) ; un composant sans l'un de ces états = **blocking review finding** (02 §11). Les états **sémantiques** §6.1 (en-cours l. 197, terminé l. 198, échec l. 199) s'appliquent **en plus** sur les éléments concernés.

### 5.1 Gestes /agent (4 gestes, owner-ratified 2026-10-05)

Les 4 gestes du chat `/agent` sont des affordances **secondaires** — jamais
substitut d'un contrôle visible (règle a11y §11 : chaque geste a son
équivalent clavier). Implémentation : `apps/mobile/src/pages/agent/index.tsx`
(pointer events ; `touch-action: none` uniquement sur la surface du
composer). Constantes (emotion-design §3 : « calm, never snappy ») : dead-zone
10 px (ni le scroll, ni le tap, ne déclenchent un geste par erreur) ; seuil
de confirmation 64 px **ou** vitesse > 0.35 px/ms (relâchement lent =
annulation, relâchement vif = action).

| # | Geste | Surface | Seuil / damping | Résultat | Équivalent accessible |
|---|---|---|---|---|---|
| G1 | Swipe **gauche** du composer | ligne du composer (hors boutons/input) | dx < −10 px actif ; confirmé dx < −64 px ou v > 0.35 px/ms | Ouvre le sheet `+` (connecteurs / recherche / skills) | Le bouton `+` (`.agent-chip`, toujours visible) |
| G2 | Swipe **droite** du composer | idem | dx > +10 px actif ; confirmé dx > +64 px ou v > 0.35 px/ms | Cycle le mode agent : `chat → agent → mirror → chat` (le registre de voix bascule avec le mode, §5.1 voice-register) | Les tabs de mode (toujours visibles, clavier ←/→) |
| G3 | Pull **bas** du composer | idem | dy > 0, damping 0.85 (transform suit le doigt, clamp 120 px) ; confirmé dy ≥ 64 px | Ouvre la modale de choix du modèle (la même que le trigger `Cpu`) | Le trigger modèle (`Cpu` / « Auto »), toujours visible |
| G4 | Peel d'une bulle `route` (deep-link 04 §3.2.5) | bulle de transcript portant un `route` (payload `data.route` OneSignal) | dx < −10 px actif (gauche uniquement), damping 0.7 ; confirmé dx < −96 px | `navigate(route, { state: { from: '/agent' } })` — la page cible s'ouvre **au-dessus** du chat ; le back natif **retourne au chat** (contexte préservé, 02 §6.3) | Le chevron de la bulle (`→` + libellé, `.agent-entry-route`) — bouton focusable, pas seulement un geste |

Règles bloquantes des 4 gestes :
- Un hint textuel discret (« Relâche pour … ») n'apparaît **que** pendant le
  geste (`.agent-composer-hint`, `aria-live="polite"`), jamais au repos —
  l'app ne « vend » pas ses propres raccourcis (AD-14 : un seul CTA par écran).
- G1/G2/G3 sont **mutuellement exclusifs** par axe dominant (le 1er move au-delà
  de la dead-zone décide de l'axe) — jamais 2 gestes sur le même mouvement.
- G4 existe **uniquement** sur les bulles qui portent un `route` ; une bulle
  sans `route` n'est jamais draggable (pas de geste fantôme).
- Pendant `thinking` (run en cours) : G1–G4 restent **actifs** (fermer/ouvrir
  les surfaces n'interrompt pas le run — AD-7), mais les tabs de mode sont
  désactivés (le mode ne bascule pas en plein run).

**Voice-register (owner-ratifié 2026-10-05)** : le registre de voix suit le
mode agent — `chat` / `agent` = vouvoiement (registre pro, emotion-design §5.1
« jamais le tutoiame ») ; `mirror` = tutoiement (registre pédagogique, le mode
miroir **enseigne** : « explique ce que tu as appris »). Le swipe G2 qui
cycle le mode **bascule** le registre (code : `registerCopy(register, …)`
dans agent/index.tsx). Les microcopy existants de l'écran suivent cette règle.

## 7. Formulaires

Le /agent n'a **pas de formulaire** au sens classique (pas de `Form` avec validation zod). Le seul champ = le `TextField` de saisie libre (§3 él. 7), qui est un **input libre** (pas un formulaire structuré).

| Champ | Lib | Validation | Clavier mobile | Persistance | SSoT |
|---|---|---|---|---|---|
| `TextField` (saisie libre) | shadcn `input` (pas ion-item — S3 l. 137 interdit) | **Aucune** validation locale (l'intention est **libre** — le kernel la **parse** côté serveur, kernel §13 : « NL utterance → Intent Engine ») ; le `TextField` **n'a pas** de label visible (c'est un **chat input**, pas un form field — 05 §3.2 l. 412 : « un champ = un seul label visible » mais un chat input **sans** label est **autorisé** si le placeholder est **exemplaire** : placeholder = « Décris ce que tu veux faire… » — pas de double emploi, 05 §3.2) | `contenteditable` (webview, ui-libraries S1 l. 170) ; Capacitor `Keyboard` pour l'avoidance (S5 l. 170) | **Local-first** : le texte **tappé** est **persisté** dans le store UI (02 §6.3 l. 426-430 : back ne perd rien, auto-persist) ; le run **n'est pas** persisté localement (AD-3 : le kernel est serveur, le run est dans `job_queue` côté serveur, kernel §7 l. 83-84) — le texte **tappé** est **local**, le résultat **est serveur** | 05 §3.2 l. 412-420 ; ui-libraries S1 l. 13, 170 ; kernel §7 |

## 8. Pagination

**Règle unique nommée** : le /agent **n'a pas de pagination** (le fil de conversation est **infini** en scroll, pas paginé — le volume de runs est **faible** (kernel §13 : une intention = 1 run, pas des centaines) ; l'historique des runs (BottomSheet) est **court** (les runs sont **récents**, pas archivés sur plusieurs pages — kernel §7 l. 83-84 : l'historique est **local**, AD-7, volume faible).

Si l'historique dépasse **100 runs** (cas **rare**, OQ-2) : `shadcn Pagination` (ui-libraries S1 l. 37 : « Pagination (list pages) `npx shadcn@latest add pagination` » ; règle volume S8 l. 304-307 : < 20 rows → shadcn Table ; 20–100 → shadcn Table + pagination ; > 100 → AG Grid virtualisé). Le /agent utilise **jamais** AG Grid (pas de table lourde, AD-14 : le /agent est **calme**). Les labels « Previous »/« Next »/« More pages » = **anglais** codés en dur dans `pagination.tsx` (a11yRefs digest) — **OQ-1** (i18n/FR : les labels ne sont **pas** thématisés, pas de SSoT FR pour les labels de pagination).

## 10. Thèmes

Comportement des 3 couches sur le /agent (05 §5 l. 2925-3306 ; overview.md §3 l. 27-54) :

- **Couche 1 — Style neutre** (Light `#FFFFFF` / Dark `#121212`) : fournit `surface`, `text-primary/secondary/muted/disabled`, `border`, `shadow` — les tokens **géométriques et sémantiques** du /agent (fond, texte des messages, Callout, Modal). Le Dark est **première classe** (sessions nocturnes, 05 §2.1.3). **Règle §9.3.1 l. 501-505** : le style neutre par défaut est **LIGHT** (`#FFFFFF`) ; le DARK n'apparaît **que** si l'utilisateur le **choisit** (settings, 05 §2.1) — **jamais** de bascule silencieuse au retour foreground.
- **Couche 2 — Thème expressif** (10 thèmes vivants : Aurora par défaut, Lagoon, Boreal, Sakura, Vesper, Solara, Terra, Verdant, Citrus, Cosmos — 05 §5.4 l. 3010-3046) : fournit `accent.primary/secondary/punctual/selected-surface` — les tokens **couleur** du /agent (le `Button primary` « Confirmer », le `Badge` scope `read`/`write`/`destructive`, les blobs du `AgentThinkingLoader` = `--aurora-accent-primary-h` / `--aurora-accent-secondary-h`, §9.3 l. 429-431). **Règle bloquante §5.1** (l. 2931-2959) : un thème **ne redéfinit JAMAIS** `success`/`warning`/`danger`/`info` — les états sémantiques (le `Callout danger` erreur, le `Callout warning` constat écart, le `Callout info` constat neutre) sont **thème-indépendants** (neutral layer). **§9.3.1 l. 494-500** : les blobs = accent only (zéro couleur inutile) ; le papillon = grayscale monochrome (lisible light + dark) ; les textes = tokens neutres (`text-secondary` / `text-muted`) — **DAPHNE check bloquant** : rendu du loader sur les **13 combinaisons** (10 thèmes + 3 presets) × 2 styles neutres.
- **Couche 3 — Presets** (Slate / Nocturne / High Contrast, 05 §5.5 l. 3153-3165) : High Contrast = `7:1 contrast`, `56px targets`, `3px focus ring` (overview §3 l. 45-49) — le `TextField` passe en `56px tap target` (ajustement, pas de nouveau composant) ; Nocturne = **monochrome** (ui-libraries §9.1 l. 384 : « Nocturne + High Contrast presets = monochrome » — le papillon du loader est **déjà** monochrome, donc le Nocturne **ne change rien** au loader, il **désature** le fond). **Le presets = comportement par couche** (05 §5.2 : 10 thèmes + 3 presets = comportement par couche, jamais de valeur par thème).
- **Local adaptation V1** = Focus Mode **uniquement** (OQ-15, 05 §5.2 l. 2961-2990 ; overview §3 l. 34-38) — le /agent **n'a pas** de local adaptation (le Focus Mode est un **preset** de Focus, pas du /agent).
- **Résolution** : `valeur = theme_accent[token] ?? style_neutre[token] ?? défaut` (05 §5.3 l. 2992-3008) — changée par `resolveToken` + `<AuroraThemeProvider>` (JSON dans `packages/ui/src/themes/`, **jamais** de changement silencieux, 05 §5.8 l. 3235-3250).

## 12. Offline

**Classe offline** (master-feature-catalog l. 73) : le /agent est **partiellement** offline — le **fil de conversation** est **local** (AD-7, kernel §7 l. 83-84), mais le **run** (exécution kernel) est **serveur** (AD-3, AD-12/F-09 : le kernel **n'exécute jamais** sur le device) :

| Élément | Classe offline (catalog) | Ce qui vit sur le **miroir local** (AD-7/AD-12) | Ce qui **meurt** (killed) |
|---|---|---|---|
| Fil de conversation | `offline-capable` (lecture AD-7) | Les messages **postés** (utilisateur + agent) sont **persistés** localement (AD-7, 02 §6.3 l. 426-430 : auto-persist) ; le fil **rester** lisible en offline (05 §4.9.1 l. 2817-2819 : « le fil restant est lisible, AD-7 ») | Le fil **reste** au kill (re-lecture du mirror, 05 §3.7 l. 1294-1300) |
| Run (exécution) | `online-required` (AD-12/F-09 : le kernel est **serveur**) | **Rien** localement (AD-3 : le kernel ne s'exécute **jamais** sur le device, kernel §2 l. 59-60) ; le `job_queue` (kernel §7 l. 83) est **serveur** | Le run **en cours** au moment du kill = **perdu** (AD-8 : le job est **persisté** côté serveur, le device **ne** le re-joue **pas** — kernel §10 l. 104-105) ; le run **réussi** = le résultat est **persisté** dans le fil (AD-7) |
| `AgentThinkingLoader` | `online-required` (la réflexion est **serveur**) | **Rien** (le loader est **transitoire**, pas persisté) | Le loader **disparaît** au kill (re-lecture = `idle`, statique) |
| Historique des runs | `offline-capable` (local, AD-7) | Les runs **terminés** (résultats) sont **persistés** localement (kernel §7 l. 83-84) | L'historique **reste** au kill (re-lecture) |
| `TextField` saisie | `offline-capable` (input local) | Le texte **tappé** est **persisté** localement (02 §6.3 l. 426-430) — mais le texte **n'est pas envoyé** au kernel sans réseau (AD-3) | Le texte **reste** au kill (re-lecture) |

**Dégradation AD-1** (master-feature-catalog l. 73) : le /agent **n'a pas** de deep-link vers une feature **désactivée** (les tool-calls sont **résolus** par le Tool Resolver, kernel §12 l. 129-130 : « the Tool Resolver picks the tool given context + availability — graceful degradation when absent, AD-1 ») : si une feature est **désactivée**, le tool **n'apparaît pas** dans le plan (le kernel **adapte**, kernel §14 l. 209 : « a disabled feature removes its capabilities from the discoverable surface — the agent **adapts** ») — le /agent **ne rend jamais** un état « feature disabled » (contrairement au 404 /agent/:runId §4 qui **existe** pour un run **inconnu**).

**Killed** (G-M2, 05 §3.7 l. 1294-1300) : le `kill-app` = un relaunch qui part du **mirror** (pas un nouvel état du moteur) : le fil de conversation + l'historique des runs sont **re-lus** localement (AD-7) ; le run **en cours** est **perdu** (le job est **persisté** côté serveur, le device ne le re-joue **pas** — kernel §10 l. 104-105 : « state lives in Postgres, executors are stateless ») ; le `AgentThinkingLoader` est en `idle` (statique) ; le `TextField` est **activé** (local input) ; **jamais** d'écran blanc ni de reset (AD-7).
