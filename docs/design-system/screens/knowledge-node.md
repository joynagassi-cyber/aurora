# Écran : knowledge-node — Nœud de connaissance (détail d'un `SemanticNode`)

> Module Knowledge · Route `/knowledge/:nodeId` (overlay IonModal sur le tab courant, 02 §6.1 S1/S3, router.tsx l.69–70) · SSoT : docs/knowledge/overview.md §4/§11/§16 + 05 §3.6.6/§3.7 l.1280 · Statut : détaillé (claimé, SSoT écran `node detail` = docs/knowledge/overview.md, pas de section 05 §4.x dédiée)

## §1 Psychologie designer

- **Objectif utilisateur** : inspecter UN nœud du savoir (concept/formule/méthode/skill) — lire `label`+`summary`+`body`, le positionner dans la hiérarchie (prérequis + liens `depends_on`/`leads_to`), voir son état de maîtrise (Acquis/Fragile/Oublié/À venir), percer sa provenance (document → page → passage, AD-11) et repartir vers l'étude (CTA « Étudier ce concept » → `/learn/:id`, context-preserving, knowledge/index.tsx:47–48 + knowledge/overview §4 « study sheet hand-off »).
- **Contexte** : mobile, main libre, réseau patchy ; ouverture depuis l'écran arbre `/knowledge` (tap nœud → `onSelectNode`, SemanticTreeRenderer.tsx:257–262) ou deep link `/knowledge/:nodeId` (router.tsx:108) ; overlay = l'utilisateur reste dans son flux (pas de navigation destructive).
- **Fréquence** : à chaque session d'étude ciblée (plusieurs fois par semaine) ; lecture locale via miroir (AD-7, docs/knowledge/overview §16 : tree browsing offline from the mirror) → consultation hors-ligne possible.
- **État émotionnel cible** : orientation (je vois où ce concept se situe dans ma matière), confiance (la provenance est traçable, AD-11), calme (pas de bruit : pas de graph chaotique, readability rule docs/knowledge/overview §17).
- **Erreur la plus probable** : `nodeId` inconnu (supprimé par consolidation merge, docs/knowledge/overview §6 « consolidation (merge duplicates) ») → l'écran renvoie `404/not-found` (état `feature-disabled`/not-found, pas de crash, ssootCode stateRefs not-found/index.tsx) ; ou `nodeId` absent du miroir local alors que le `fetch` serveur échoue → `Callout danger` + retry, le contexte local (branches déjà syncées) reste affiché (05 §3.7 l.1280 `SemanticTreeNode` = « sous-arbre reste »).
- **Ce que l'écran RÉSOUT** : une vue de **détail lisible** d'un nœud (pas le graphe entier) : identité + état de maîtrise + métadonnées + préréquis/liens + provenance + CTA d'étude. La vérité = Knowledge (AD-6, docs/knowledge/overview §2) ; l'écran **n'écrit rien** dans `semantic_*` (AD-2/F-02, docs/knowledge/overview §24 : l'agent *request*, ne write jamais la structure).

## §2 Contexte fonctionnel

- **Entrée** : depuis `/knowledge` (tap nœud, `onSelectNode` — SemanticTreeRenderer.tsx:257–262) ou deep link `/knowledge/:nodeId` (router.tsx:108) ; sortie vers `/learn/:id` (CTA « Étudier ce concept », context-preserving 02 S6.2, knowledge/index.tsx:47–48).
- **Overlay IonModal `/knowledge/:nodeId`** (router.tsx l.69–70 detail-over-tab rule 02 §6.1 S1/S3) : le tab courant reste sous l'overlay (pas de navigation destructive).
- **Data** : `SemanticNode` (kind ∈ principle/domain/subject/concept/law/formula/method/example/application/skill ; label/summary/body/parent/domain_path, supabase/migrations/0004_knowledge.sql:43–61) + `NodeState` (state ∈ collapsed/expanded/selected/focused/mastered/fragile/forgotten, 0004:91–103) + `SemanticEdge` (relation ∈ depends_on/is_a_case_of/deepens/applies/leads_to, 0004:63–75) + `SourceRef` (entity/page/passage, 0004:113–120) — consommés depuis `@aurora/domain` (AD-15, 02 §5.1 l.287–288), **jamais** redéfinis par l'écran.
- **Async** : lecture = **locale** (miroir AD-7/AD-12, docs/knowledge/overview §16 : tree browsing offline from the mirror, deeper branches lazy) ; la **retrieval** sémantique = **serveur-only** (AD-12/F-09, docs/knowledge/overview §11 : device never runs semantic retrieval locally) → killed possible sur ce flux **uniquement** (le détail d'un nœud déjà syncé reste lisible offline).
- **État de sélection** : l'écran **lit** `NodeState.selected/focused` (docs/knowledge/overview §2 : Knowledge is the sole writer of NodeState, AD-6) ; l'écran **n'écrit JAMAIS** `NodeState` ni `semantic_*` (AD-2/F-02, docs/knowledge/overview §24 : inspect/link/explain = read-only). L'état d'expansion du nœud est persisté dans le `ui-state` store (knowledge/index.tsx:20, `knowledgeExpanded`).

## §4 États (matrice complète AD-13 / 05 §3.7 l.1244–1309)

### (a) 6 états S6 par élément async (ui-libraries §6 l.174–187)

- **success** (nœud chargé + étude lancée depuis ce nœud) : zone contenu = nœud complet + CTA « Étudier ce concept » actif ; tokens = --aurora-success (si QCM validé depuis `/learn/:id`, retour sur cet écran = Badge maîtrisé) ; **entrée** = fade 200ms ; **sortie** = tap CTA → `/learn/:id` (context-preserving, 02 S6.2).
