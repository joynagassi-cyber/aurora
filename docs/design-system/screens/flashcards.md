# Écran : flashcards — Flashcards (révision FSRS)

> Module Learning · Route `/learn/:id` (overlay IonModal sur le tab courant, 02 §6.1 S1/S3, router.tsx l.97) · SSoT 05 §4.8.1 l.2640–2697 + WDS 01.3 · Statut : détaillé

## §1 Psychologie designer

| Dimension | Valeur |
|---|---|
| **Objectif utilisateur** (1 ligne) | Réviser une matière par flashcards à répétition espacée (FSRS) : lire le recto, révéler le verso par tap (jamais d'auto-flip), auto-évaluer en 4 niveaux, terminer la session. |
| **Contexte** | Mobile, main libre, sessions courtes ; réseau patchy probable ; ouverture depuis home (bloc « révisions dues », AD-14) ou depuis cours-detail / fiches-liste ; overlay = l'utilisateur reste dans son flux (pas de navigation destructive). |
| **Fréquence** | Quotidienne à hebdomadaire — la révision espacée est le moteur de rétention du module Learning ; chaque session = plusieurs sessions courtes par semaine. |
| **État émotionnel cible** | Flow (rythme carte → flip → évaluation), confiance (progression fine visible « Carte 3/12 »), calme (pas de punition : échec = « Oublié » = carte qui revient plus tôt, pas d'alerte rouge), motivation (EmptyState positif « Toutes les révisions sont à jour »). |
| **Erreur la plus probable** | Tap par erreur avant le flip (le verso se révèle trop tôt) — mitigation = le flip n'est déclenché que par le bouton « Voir le verso », jamais auto-flip (05 §3.6.10) ; tap sur une carte au contenu indisponible → Callout warning, la carte reste dans la file (révision différée, pas d'élimination silencieuse). |
| **Ce que l'écran RÉSOUT** | File de révision actionnable 100 % locale (miroir AD-7, FSRS exécuté côté serveur au re-sync) : composition 3 zones fixes + BottomNav (WDS 01.3 §6) ; la révision reste actionnable hors-ligne (AD-1), les résultats FSRS sont calculés côté serveur et synchronisés au re-sync (05 §4.8.1 ; callout info). |

## §2 Zones (cartographie de l'écran)

- **Header (TopBar)** : bouton retour + titre « Flashcards » + `SegmentedControl` par matière (filtre de la file de révision) + `ProgressBar` fine de la session de révision en cours + badge offline (si état offline, S6 ui-libraries §6 l.184).
- **Zone progression** : badge « Carte 3/12 » (`JetBrains Mono xs`, 05 §2.2) + timer de session affiché par défaut (WDS 01.3 OQ-2, tranché 09/25 : affiché, **pas** masquable).
- **Zone carte centrale** : `FlashcardCard` recto/verso (recto = question, verso = réponse ; contenu fidèle au corpus, AD-11 ; radius xl, shadow.2, 05 §2.4) + bloc d'explication d'Aurora **labelisé séparé** du contenu du cours (règle AD-11 §3.6.10) + `MathBlock` (KaTeX) si la carte contient une formule (05 §3.6.8).
- **Barre de rétroaction FSRS** : 4 boutons d'auto-évaluation sous la carte (tranché WDS 01.3 OQ-1 : oublié/difficile/bon/facile) — « Oublié » (danger), « Difficile » (warning), « Bon » (success), « Facile » ; 44px ; choisis **après** le flip.
- **Zone actions flottantes** : `Button ghost` « Terminer la session » + `Button primary` « Lancer la session » (mode file de révision, avant session).
- **Fin de file / Zone 3** : CTA fixe « QCM du domaine » (`Button primary`), visible **uniquement** en fin de file (12/12) — seul CTA d'action de la surface (invariant AD-14, WDS 01.3).
- **BottomNav** : 5 tabs partagées (Home · Kanban · Calendar · Progress · Agent, S-31).
- **Zones états** : Callout / EmptyState / Skeleton selon l'état S6 (ui-libraries §6) + états sémantiques screen-level (ui-libraries §6.1).

## §4 États (matrice complète AD-13 / 05 §3.7)

### (a) 6 états S6 par élément async (ui-libraries §6 l.174–187)

- **loading** (chargement de la file de révision locale, AD-7) : Skeleton recto/verso (shape carte finale, 05 §3.6.10 ; si `MathBlock` = skeleton de bloc formule) ; tokens = --aurora-skeleton ; texte exact = « Chargement de la file… » (court, local AD-7) ; CTA = aucun (pas d'actions avant données) ; **entrée** = fade 200ms easeOut (PAGE_TRANSITION, ssootCode motionRefs polish.tsx) ; **sortie** = skeleton → carte crossfade 200ms (si > 300ms le contenu apparaît partiellement en dessous, pack 02 §7) ; **portée** = chargement de la file de révision locale + rendu de la `FlashcardCard` (recto/verso, si `MathBlock`) = 2 éléments de §3 avec état S6 loading distinct.
- **empty** (file de révision à jour, aucune carte due) : EmptyState « Toutes les révisions sont à jour » + CTA primary « Réviser une autre matière » (05 §12 : état vide **positif** ; pack 02 §7 : jamais un bloc vide) ; tokens = --aurora-bg-subtle + --aurora-text-secondary ; **entrée** = fade 200ms ; **sortie** = tap CTA → SegmentedControl / navigation vers la matière choisie (flux loading de la nouvelle file) ; **portée** = `EmptyState` + CTA « Réviser une autre matière » = 1 élément §3 (EmptyState avec CTA intégré, 05 §12).
- **error** (fiche manquante : contenu de la carte indisponible) : Callout warning (état error, 05 §3.6.10) — la carte **reste dans la file**, révision différée (pas d'élimination silencieuse) ; tokens = --aurora-warning / --aurora-warning-surface (frozen, 05 §5.1) ; CTA = aucun sur le callout (la carte est surlignée, on passe à la suivante) ; **entrée** = fade 200ms ; **sortie** = tap « Suivant » → carte suivante ; **pas** de Callout qui disparaît (AD-7 : l'erreur est affichée) ; **portée** = Callout warning fiche manquante + `FlashcardCard` (état error) = 2 éléments §3 ; la carte reste dans la file.
- **success** (fin de session, session terminée et synchronisée) : Toast success S6 l.183 (check vert, auto-dismiss 3s) ; tokens = --aurora-success (frozen) ; texte exact = « Session terminée — N cartes révisées » ; CTA = CTA fixe « QCM du domaine » (Zone 3, s'il apparaît) ; **entrée** = toast slide up 200ms easeOut (translateY, pas de layout, S5 l.169) ; **sortie** = auto-dismiss 3s (§3.5 l.823) ; **portée** = Toast de fin de session + CTA fixe « QCM du domaine » (Zone 3) = 2 éléments §3.
- **offline** (réseau coupé, révision locale OK) : Offline badge en TopBar (S6 l.184, texte = OQ-04 §14) + Callout info « Les résultats FSRS seront calculés à la connexion » — la révision **reste actionnable** (miroir AD-7, 05 §4.8.1) ; tokens = --aurora-info (frozen, 05 §5.1) + --aurora-warning (badge) ; CTA = boutons FSRS restent actifs (les résultats sont calculés au re-sync, serveur), génération/QCM désactivés (pas de CTA serveur) ; **entrée** = fade 200ms ; **sortie** = retour online → re-sync (les résultats FSRS sont calculés côté serveur, 05 §4.8.1) ; **portée** = Offline badge TopBar + Callout info offline + désactivation CTA « QCM du domaine » / génération = 3 éléments §3 ; la révision reste actionnable (miroir local).
- **killed** (flux serveur mort : FSRS re-sync, AD-13/G-M2) : Skeleton + « Reconnexion… » (S6 l.185) ; tokens = --aurora-skeleton (+ --aurora-danger pour le badge d'état) ; CTA = **aucun** (pas de retry, pas de navigation, ssootCode stateRefs ux-states.tsx) ; **entrée** = fade 200ms ; **sortie** = reconnexion OK → re-sync FSRS serveur → loading/success ; le contenu **local** (file de révision, AD-7) reste lisible en dessous (pas de crash, pas de perte de contenu local) ; **portée** = re-sync FSRS serveur (flux serveur uniquement, §4d) ; la révision locale reste inchangée et actionnable (AD-7).

### (b) États sémantiques §6.1 (ui-libraries l.189–202)

- **en-cours** (session de révision en cours, carte X/12, évaluations partielles) : ProgressBar fine (05 §3.3) + Badge « Carte X/12 » + timer de session (zone progression, WDS 01.3 OQ-2 affiché par défaut) ; tokens = --aurora-accent-primary (barre) + --aurora-text-secondary (badge/timer) ; CTA = boutons FSRS actifs (pas de blocage) ; source = 05 §3.3 + ui-libraries §6.1 l.197 (progression **mesurable** = ≠ S6 loading).
- **terminé** (session terminée, 12/12, re-sync local OK) : Zone 3 = CTA fixe « QCM du domaine » (Button primary, seul CTA d'action, AD-14) + Toast success (S6 l.183, auto-dismiss 3s) ; tokens = --aurora-success ; CTA = « QCM du domaine » (sortie, §4.8.2) + « Réviser une autre matière » (si empty suivant) ; source = ui-libraries §6.1 l.198 (terminé = état de l'**objet**, ≠ S6 success transient).
- **échec** (fiche manquante : carte dont le contenu est indisponible) : Callout warning (état error, 05 §3.6.10) — la carte **reste dans la file**, révision différée ; tokens = --aurora-warning (frozen, 05 §5.1) ; CTA = **aucun** CTA d'alternative dans l'écran (la carte est repoussée, pas de retry in place, ≠ S6 error transient) ; source = ui-libraries §6.1 l.199 (échec = terminal, pas de retry in place).
- **succès / erreur générique** = N/A (raison : pas d'écriture dans l'écran — la révision est une lecture + évaluation locale, pas de mutation locale ; tout succès/erreur = Callout/Toast §4a, pas d'état sémantique d'écran propre).
