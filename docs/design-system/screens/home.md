## 2. Zones

Composition **fixe et ordonnée** (pack 02 §6.2 — toute dérive = blocking) :

- **header** : un `TopBar` (05 §3.4 l. 659-668) — « Aujourd'hui » + la date (`xs`, `JetBrains Mono`, `text-muted` sous-titre) + **2 `IconButton`** : recherche, menu. **Pas de `back`** (écran racine, règle AD-14 05 §3.4 l. 667-670). Le Home **date toujours** son contenu (ancrage temporel de non-surprise).
- **content** : les **7 blocs, dans cet ordre** (05 §4.1.2 l. 1368-1390) :
  1. `Agenda du jour` — liste de `ListItem subtitle` (événements + tâches du jour, heure en `JetBrains Mono` `xs`)
  2. `Prochaine action importante` — un **seul** `Card elevated` (titre de la tâche + projet/matière en `Badge`, CTA « Démarrer le Focus » si c'est l'action du moment)
  3. `Priorité principale` — `ListItem` dense (masquée si identique au bloc 2)
  4. `Progression critique` — `ListItem` dense + `SkillStateBadge` (élément Progress le plus urgent, doc §18.1)
  5. `Révisions à effectuer` — `Chip` compteur « 12 révisions dues » `primary` + CTA ghost « Réviser » → ouvre `flashcards` §4.8.1
  6. `Accès Focus` — `Button primary` **large** (`lg`, 56px) vers `focus-mode` §4.4.2 (le 6ᵉ bloc est un **bouton**, pas une liste)
  7. `Suggestions Coach` — 1-2 max, `Callout info` posé (pas un toast), CTA de chaque suggestion
- **footer** : `BottomNav` (5 items figés : Accueil / Tâches / Apprendre / Progression / Coach ; 05 §3.4 l. 670-688)
- **surfaces flottantes** : `BottomSheet` de capture (CTA empty « Capturer une idée »), `Menu` de tri, `Toast`/`Snackbar` (file max 1), et le `FAB` **n'existe PAS** au Home (interdit : l'accueil est calme, le FAB vit dans les écrans de création — 05 §3.1 l. 406-408 « le FAB est un mobile-only pattern… interdit au Home » ; OQ-2).

## 10. Thèmes

Comportement des 3 couches sur le Home (05 §5 l. 2925-3307 ; overview.md §3 l. 27-54) :

- **Couche 1 — Style neutre** (Light `#FFFFFF` / Dark `#121212`) : fournit `surface`, `text-primary/secondary`, `border`, `shadow` — les tokens **géométriques et sémantiques** du Home (fond, texte, ombres). Le Dark est **première classe** (sessions nocturnes §2.8, `#121212` plain dark, pas `#000` pour éviter le banding OLED — overview §2 l. 17-23).
- **Couche 2 — Thème expressif** (10 thèmes vivants : Aurora par défaut, Lagoon, Boreal, Sakura, Vesper, Solara, Terra, Verdant, Citrus, Cosmos — 05 §5.4 l. 3010-3046) : fournit `accent.primary/secondary/info/focus-ring` — les tokens **couleur** du Home (le `Button primary` bloc 6, le `Chip` compteur bloc 5, la `ProgressBar` du bloc 2). **Règle bloquante §5.1** : un thème **ne redéfinit JAMAIS** `success`/`warning`
/danger`/`info` — les états sémantiques (le `Callout info` bloc 7, le `Badge danger` « à resync ») sont **thème-indépendants** (neutral layer, 05 §5.1 l. 2931-2959 ; overview §3 l. 39-43).
- **Couche 3 — Presets** (Slate / Nocturne / High Contrast, 05 §5.5 l. 3153-3165) : High Contrast = `7:1 contrast`, `56px targets`, `3px focus ring` (overview §3 l. 45-49 ; 05 §6.3) — le `Button` lg (bloc 6, 56px) reste **identique** (56px = déjà le target High Contrast, pas de changement) ; le `Chip` compteur (bloc 5) passe en `56px tap target` (ajustement, pas de nouveau composant).
- **Local adaptation V1** = Focus Mode **uniquement** (OQ-15, 05 §5.2 l. 2961-2990 ; overview §3 l. 34-38) — le Home n'a **pas** de local adaptation (le Focus = bloc 6 qui **mène vers** `/focus`, pas une adaptation du Home).
- **Résolution** : `valeur = theme_accent[token] ?? style_neutre[token] ?? défaut` (05 §5.3 l. 2992-3008) — changée par `resolveToken` + `<AuroraThemeProvider>` (JSON dans `packages/ui/src/themes/`, **jamais** de changement silencieux au foreground, 05 §5.8 l. 3235-3250).
