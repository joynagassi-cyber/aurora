# Composite Workflows (end-to-end, cross-module)

Status: design phase. Each workflow lists: Trigger · Actors · Modules · Capabilities ·
Data · Events · Jobs · UI transitions · Agent actions · Permissions · Failure points ·
Recovery. Channels are normative (AD-2/AD-7/AD-9): command = write to owner; event =
the 9; view = cross-module read. UI = `apps/mobile` slice (02 §4); "S" = server-side
job/gateway (01 §5).

## W1 Study Session
- **Trigger**: user opens a course/chapter, or Agent plans a session · **Actors**: user, Learning module, Agent (Tutor), Scientific Engine · **Modules**: Learning → Knowledge → (Scientific) · **Capabilities**: `learning.session.start`, `qcm.generate`, `scientific.evaluate` · **Data**: `learning_sessions` (+mode), `flashcards` FSRS state, semantic nodes, R2 document · **Events**: `FlashcardReviewed` · **Jobs**: S `fsrs-tick`, generation (sheet/QCM) · **UI**: course → chapter → sheet/flashcards/QCM (05 §4.6–4.8) · **Agent**: Tutor explains (fidelity AD-11), verifies answers (engine for math) · **Permissions**: camera/mic optional (capture) · **Failures**: provider down → fallback chain (AD-5); OCR absent → manual entry · **Recovery**: local mirror; jobs retry idempotent.

## W2 Exam Preparation
- **Trigger**: due date in calendar + user goal, or Agent proactive (Coach check-in, ADR §13) · **Actors**: user, Agent (Planner+Coach), Learning, Productivity · **Modules**: Productivity (planning) → Learning (materials) → Progress (measurement) · **Capabilities**: `calendar.schedule`, `learning.sheet.generate`, `flashcard.generate`, `progress.analyze` · **Data**: `goals` (exam horizon), `courses`, calendar + time blocks · **Events**: `GoalUpdated`, `TaskCompleted` · **Jobs**: S generation + planning SLOs · **UI**: Home (AD-14 due reviews) → agenda/time-blocking → focus · **Agent**: builds a realistic plan (load check, ADR §6), dynamic replan on deviation · **Permissions**: local notifications (reminders) · **Failures**: overload detected → Agent proposes trimmed plan (confirmation) · **Recovery**: plan history preserved (ADR §13 "sans détruire l'historique").

## W3 Daily Planning
- **Trigger**: morning check-in (Coach) or user · **Actors**: user + Agent (Planner) · **Modules**: Productivity (calendar, tasks, habits) · **Capabilities**: `planning.daily` · **Data**: today's `tasks`/`events`/`habits` + actual available time · **Events**: `TaskCompleted` (re-plan) · **Jobs**: none (light, local + AI router ROUTINE/AGENT) · **UI**: Home → agenda → time blocking · **Agent**: prioritization (Eisenhower signals, eisenhower.md §6) + explanations · **Permissions**: none · **Failures**: missing estimates → agent asks/infers (flagged) · **Recovery**: plan = local state, instant.

## W4 Weekly Planning
- **Trigger**: weekly review (05 §4.5) or Agent · **Actors**: user + Agent · **Modules**: Productivity + Progress · **Capabilities**: `planning.weekly`, `progress.analyze` · **Data**: week actuals vs plan, `decisions` journal · **Events**: `GoalUpdated` · **Jobs**: S trend recompute · **UI**: reviews screen → next-week agenda · **Agent**: cause analysis of slippage (ADR §18.4), priority review · **Permissions**: none · **Failures**: missing data → agent degrades to manual review prompts · **Recovery**: journals local.

## W5 Concept Coaching
- **Trigger**: user flags "I don't understand X", or Agent detects a gap · **Actors**: user + Agent (Tutor) · **Modules**: Knowledge (retrieval) → Learning (practice) → Progress (evidence) · **Capabilities**: `knowledge.retrieve`, `qcm.generate`, `flashcard.generate` · **Data**: semantic node + sources (AD-11 provenance) · **Events**: `FlashcardReviewed`, Progress evidence jobs · **Jobs**: S critical-verify when math involved (engine) · **UI**: knowledge node → explanation (separated corpus vs Aurora, AD-11) → active recall · **Agent**: explains + questions; corpus fidelity · **Permissions**: none · **Failures**: retrieval miss → suggested actions (empty state 02 §7) · **Recovery**: node state updated via AD-9 chain only.

## W6 Mirror Cognitive Mode
- **Trigger**: user explains a concept (text Tiptap / audio) · **Actors**: user + Agent (Tutor, server job `mirror-analysis`) · **Modules**: Learning (session) → Progress (evidence) → Knowledge (`NodeState`) · **Capabilities**: `learning.mirror.analyze` · **Data**: `learning_sessions.mode='mirror'` + typed findings (lacune/contradiction/erreur) with corpus provenance · **Events**: `ProgressEvidenceCreated` (Progress-qualified, F-07), `SkillStateChanged` · **Jobs**: S `mirror-analysis` · **UI**: coach-mode family (05 §4.8/4.9) → structured feedback → optional flashcards/QCM on gaps · **Agent**: detects gaps/contradictions/errors, quotes the professor's formulations (no creative rewrite, ADR §17) · **Permissions**: mic optional · **Failures**: STT absent → text mode; analysis timeout → partial findings + retry · **Recovery**: session row persisted; findings idempotent.

## W7 Discovery → Learning
- **Trigger**: `DiscoveryItemCreated` (event) or user opens a discovery sheet · **Actors**: Discovery module → Learning · **Modules**: Discovery → Learning (+Knowledge links, +Progress measurement) · **Capabilities**: `discovery.sheet.open`, `learning.activity.create` · **Data**: `discovery_items` (typed sources: FACT/TREND/ANALYSIS/SCENARIO/UNCERTAINTY, ADR §13.7) · **Events**: `DiscoveryItemCreated` · **Jobs**: S multi-source research · **UI**: discovery feed → sheet → "work on this" → Learning activity · **Agent**: explains the discovery, links to existing knowledge (ADR §13.9 loop) · **Permissions**: none · **Failures**: `ResearchProvider` absent → `uncertain`-marked items (01 §6) · **Recovery**: items persisted; research jobs retry.

## W8 Course → Revision (sheet)
- **Trigger**: import completes (`CourseImported`) or user request · **Actors**: Learning + Agent · **Modules**: Learning → Knowledge → Artifact (export) · **Capabilities**: `course.search`, `learning.sheet.generate` · **Data**: course content (R2) + semantic tree + sheet structures (ADR §17 sheet types) · **Events**: `CourseImported` (→ Knowledge/Discovery/Progress) · **Jobs**: S OCR (if scanned) → extraction → sheet generation → export (MD/PDF/DOCX/PNG, ADR §17) · **UI**: import screen → sheet screen (05 §4.7) → Artifact Hub preview · **Agent**: extracts definitions/formulas/traps with fidelity + fidelity check before export · **Permissions**: camera (scan) · **Failures**: OCR/STT absent → manual; fidelity drift → flagged blocks (never silent) · **Recovery**: idempotent jobs; export = `ArtifactGenerated` post-R2 (F-06).

## W9 Course → Flashcards
- **Trigger**: sheet ready, or "send to FSRS" (ADR §17 long-term items) · **Actors**: Learning · **Modules**: Learning · **Capabilities**: `flashcard.generate` · **Data**: `flashcards` + FSRS state (server algorithm, 03 §4.2) · **Events**: `FlashcardReviewed` · **Jobs**: S `fsrs-tick` · **UI**: flashcards screen (05 §4.8) · **Agent**: derives cards from sheet gaps (structured output) · **Permissions**: none · **Failures**: FSRS recompute delay → local state mirror used, server wins later · **Recovery**: due lists recomputed by job.

## W10 Course → QCM
- **Trigger**: sheet/exercise generation, or targeted revision (`SkillStateChanged`) · **Actors**: Learning + Agent · **Modules**: Learning → Progress (evidence) · **Capabilities**: `qcm.generate` · **Data**: QCM items + attempt records · **Events**: `FlashcardReviewed` family (evidence via Progress, F-07) · **Jobs**: S generation · **UI**: QCM screen → result + recurring-error analysis (ADR §3) · **Agent**: generates from corpus (fidelity), adapts difficulty (Progress) · **Permissions**: none · **Failures**: generation fallback (AD-5) → degraded-quality flag · **Recovery**: attempts persisted.

## W11 Course → Exercise → Progress
- **Trigger**: user completes an exercise · **Actors**: user → Learning → Progress · **Modules**: Learning → Progress → (Knowledge `NodeState`) · **Capabilities**: `learning.exercise.submit` · **Data**: exercise results → `ProgressEvidence` (Progress-qualified, F-07) → `SkillState` · **Events**: `ProgressEvidenceCreated` → `SkillStateChanged` · **Jobs**: S `skill_recompute` · **UI**: exercise screen → result → Progress dashboard · **Agent**: explains errors (corpus + engine), proposes rework · **Permissions**: none · **Failures**: recompute lag → dashboard shows last mirror (stale marking) · **Recovery**: recompute is idempotent.

## W12 Goal → Project → Task
- **Trigger**: user sets a goal (short/mid/long horizon) · **Actors**: user + Agent (Planner) · **Modules**: Productivity · **Capabilities**: `goal.create`, `project.create`, `task.create` · **Data**: `goals` (FK user, horizon) → `projects` → `tasks` (01 §4.1 relations) · **Events**: `GoalUpdated` · **Jobs**: none (local commands + upsync) · **UI**: goals → project board (Kanban/Gantt/Timeline, 05 §4.3) · **Agent**: decomposes goal into milestones/tasks (confirmation for bulk create) · **Permissions**: none · **Failures**: missing horizon → agent asks (inferred params flagged) · **Recovery**: local commands, upsync queue.

## W13 Task → Focus → actual time
- **Trigger**: user starts Focus on a task (or Agent suggests) · **Actors**: user (+DPC mode if provisioned) · **Modules**: Productivity (Focus) · **Capabilities**: `focus.start`, v1.8 `focus.block` (DPC) · **Data**: `focus_sessions` (+`task_id`, blocklist, snapshot — focus spec §6) · **Events**: none dedicated (bilan → W9/W11 evidence chain) · **Jobs**: none (device capability) · **UI**: task → focus screen (05 §4.4.2) → bilan sheet (ChartSpec `focusBilan`) · **Agent**: proposes focus when Q1 tasks overload (explanation) · **Permissions**: `POST_NOTIFICATIONS` optional; DPC = OQ-17 · **Failures**: DPC pre-check rejects packages → restricted fallback; timer survives kill (system clock) · **Recovery**: session row + boot receiver (focus spec §7).

## W14 Focus → Progress (discipline)
- **Trigger**: session end · **Actors**: Productivity → Progress · **Modules**: Progress · **Capabilities**: `progress.analyze` · **Data**: `FocusSessionBilan` (SSoT 01 §4.1) → evidence (planned vs actual, interruptions) → `skill_states`/`progress_snapshots` mirrors · **Events**: `ProgressEvidenceCreated` · **Jobs**: S evidence qualification · **UI**: Progress dashboard (today/week views, ADR §18.6) · **Agent**: stagnation → cause analysis before new recommendation (ADR §18.7) · **Permissions**: none · **Failures**: evidence lag → dashboard last-known state · **Recovery**: jobs idempotent.

## W15 Progress → Replanning
- **Trigger**: detected delay/stagnation (`ProgressTrend`) or user request · **Actors**: Progress → Agent → Productivity · **Modules**: Progress, Agent, Productivity · **Capabilities**: `planning.replan`, `progress.analyze` · **Data**: trends + `decisions` journal · **Events**: `GoalUpdated` (after user confirms new priorities) · **Jobs**: S analysis · **UI**: Progress → "next actions" → agenda · **Agent**: proposes replan (causes, ADR §18.4); **confirmation mandatory** (AD-12/ADR §5) · **Permissions**: none · **Failures**: analysis inconclusive → human review prompt · **Recovery**: original plan preserved (history).

## W16 Research → Artifact
- **Trigger**: user request ("find me…") or Agent discovery · **Actors**: Agent (Researcher) + Discovery + Artifact · **Modules**: Discovery → Artifact → Knowledge · **Capabilities**: `discovery.research`, `artifact.generate` · **Data**: `discovery_items` (typed sources + uncertainty, ADR §13.2/§13.7) · **Events**: `DiscoveryItemCreated`, `ArtifactGenerated` (post-R2, F-06) · **Jobs**: S research + artifact render · **UI**: discovery feed → sheet → Artifact Hub (05 §4) · **Agent**: cross-checks sources, marks uncertainty, never presents a projection as fact (ADR §13.7) · **Permissions**: provider keys server-only (AD-3) · **Failures**: provider down → fallback/`uncertain` (01 §6) · **Recovery**: jobs retry; items persist.

## W17 Audio → Transcription → Knowledge
- **Trigger**: user records an audio course (or imports) · **Actors**: user + server jobs · **Modules**: Learning (audio artifact) → Knowledge → Semantic Tree → Learning/Progress · **Capabilities**: `audio.record`, `transcription.run` (optional), `knowledge.ingest` · **Data**: R2 audio + transcript + segments → concepts → semantic nodes · **Events**: `CourseImported` (if course audio), `DiscoveryItemCreated` n/a · **Jobs**: S `transcription` (optional provider) → segmentation → concept extraction (ADR v1.5 pipeline; heavy = jobs, never blocks UI) · **UI**: audio viewer (`AudioWaveformRenderer`, pure DS component 04 §5) → timestamps → concepts · **Agent**: structures the transcript (provenance = audio segment, AD-11) · **Permissions**: mic · **Failures**: STT absent → audio playable, transcript optional (AD-1 degradation) · **Recovery**: jobs idempotent; viewer local.

## W18 OCR → Knowledge
- **Trigger**: document scan (`DocumentScanner`) · **Actors**: user + server job · **Modules**: Knowledge (+Learning if a course) · **Capabilities**: `document.scan`, `ocr.run` (optional) · **Data**: R2 image → structured text → document + chunks + embeddings (pgvector) · **Events**: `CourseImported` (course path) · **Jobs**: S `ocr` + embedding generation · **UI**: scanner screen (multi-page) → import status → tree node (05 §4) · **Agent**: extracts definitions/formulas (fidelity, ADR §17) · **Permissions**: camera · **Failures**: OCR absent/low quality → manual entry (01 §6) · **Recovery**: re-scan; embeddings recomputed.

## W19 Knowledge → Semantic Tree
- **Trigger**: `CourseImported`/search results/`DiscoveryItemCreated` · **Actors**: Knowledge module · **Modules**: Knowledge · **Capabilities**: `knowledge.ingest` · **Data**: `semantic_nodes/edges/bridges` (hierarchy + annotated cross-domain bridges, ADR §14), `source_refs`, `node_state` (Knowledge-only writer, AD-6), `semantic_tree_version` · **Events**: consumed: `CourseImported`, `DiscoveryItemCreated`, `ProgressEvidenceCreated`, `SkillStateChanged` · **Jobs**: S ingestion/consolidation (duplicate merge on sufficient evidence, ADR §14) · **UI**: tree screen (lazy level-1 + incremental Dagre, 30 fps — 02 §9.2) · **Agent**: tree = Semantic Context form (AD-12) · **Permissions**: none · **Failures**: no local semantic retrieval (server-only, AD-12) → offline = browse mirror only · **Recovery**: version table restores prior tree state.

## W20 Focus Session (standalone, no task)
- **Trigger**: user starts a plain focus block · **Actors**: user · **Modules**: Productivity · **Capabilities**: `focus.start` · **Data**: `focus_sessions` (no `task_id`) · **Events**: none · **Jobs**: none · **UI**: focus screen + timer (Pomodoro 25 min default) · **Agent**: Coach may check in after (ADR §13, cadence respected) · **Permissions**: as W13 · **Failures**: as W13 · **Recovery**: session row.

## W21 Calendar Conflicts & Overload
- **Trigger**: schedule change or Agent load check · **Actors**: Productivity (+Agent) · **Modules**: Productivity · **Capabilities**: `calendar.schedule` · **Data**: `events` + time blocks + estimates · **Events**: `GoalUpdated` when horizons shift · **Jobs**: none · **UI**: calendar/agenda screens (05 §4.4) with conflict/overload badges · **Agent**: replans around conflicts (explanation) · **Permissions**: local notifications · **Failures**: missing estimates → flagged assumptions · **Recovery**: calendar = local mirror.

## W22 Artifact Preview & Export
- **Trigger**: open an artifact (imported or generated) · **Actors**: user · **Modules**: Artifact + renderers · **Capabilities**: `artifact.open`, `artifact.export` · **Data**: R2 object + `artifacts` metadata (`r2_key`, 03 §4.2 rule: binaries never in SQLite) · **Events**: `ArtifactGenerated` (producer), `JobCompleted` (state) · **Jobs**: S export render (formats, ADR §17) · **UI**: Artifact Hub preview per format (PDF/DOCX/PPTX/XLSX/images/audio/LaTeX, ADR §16; unsupported = kept + downloadable, **no preview claim**) · **Agent**: generates on request (never emits `ArtifactGenerated` itself — F-06) · **Permissions**: presigned URLs only (AD-3) · **Failures**: preview engine error → raw file fallback · **Recovery**: re-download/re-generate.

## W23 Habit/Routine Loop
- **Trigger**: daily/weekly anchors (routines) or review · **Actors**: user + Agent (Coach) · **Modules**: Productivity (+Progress for adherence analytics) · **Capabilities**: `habit.checkin`, `planning.daily` · **Data**: `habits`/`routines` (+time anchors), adherence series · **Events**: `TaskCompleted` (habit tasks) · **Jobs**: S analytics aggregation · **UI**: habit heatmap (`HabitStreak`, 05 §3.6.12) + review screens · **Agent**: disruptive-habit detection (ADR §2.7) + routine adaptation suggestions · **Permissions**: local notifications · **Failures**: missed check-in = honest streak break (no silent correction) · **Recovery**: local data.

## Cross-workflow invariants

Every workflow: **single-writer commands** (AD-7) · **only the 9 events** (AD-9) ·
**heavy = idempotent jobs** (AD-8) · **fidelity + provenance** where corpus-adjacent
(AD-11) · **5 UX states per screen** (AD-13) · **offline-first degradation, not
failure** (AD-7) · agent actions confirmed when important/irreversible (ADR §5,
AD-12 Permission Context).
