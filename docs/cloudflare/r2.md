# Cloudflare R2 (files only — never business metadata)

Status: design phase. Authority: 01 §4.6/§5.4, 03 §4.2 rule 2 (files never in
SQLite), 04 §3.2.2 (client upload), AD-3/AD-16. R2 = object storage; **structure and
content live in PostgreSQL** (spine Stack); buckets are per-environment, **private**,
names = wave-0 data (OQ-03), owner Foundation (AD-16a/AD-16c).

## 1. Objects & naming (prescriptive, additive — owner `packages/data` at wave 0)

- **Key convention**: `{env}/{user_id}/{module}/{yyyy}/{mm}/{dd}/{ULID}[_{slug}].{ext}`
  (ULID = upload id; per-user prefix = ownership is readable in the key itself).
- **Content type**: recorded at upload (`mime`); large media (audio/video) use the
  real MIME; generated artifacts carry their export format (`md|pdf|docx|png`, ADR
  §17).
- **Size**: small docs via presigned PUT (TTL 5 min, 01 §5.4); **multipart upload
  for large artifacts** (audio/video > ~50 MB — threshold = wave-0 data) using the
  same presigning flow (R2 multipart API behind the Edge Function).

## 2. The ownership chain (who does what — mission §21, explicitly)

| Question | Answer (normative) |
|---|---|
| Who creates the presigned URL? | **Server Edge Functions only** (`fn-*` presigning, 01 §5.4); the client never holds R2 keys (AD-3; 04 §7.2b anti-leak test) |
| Who uploads? | Imported/captured files: **the app directly to R2** via the presigned URL (`LocalFileStorageAdapter.upload`, 04 §3.2.2); generated artifacts: **the server job** writes to R2 |
| Who validates ownership? | The presign function validates the **user's JWT** + module scope (RLS-consistent, 01 §2.2) **before** issuing the URL; on upload completion a server check creates/links the metadata row |
| Who downloads? | App via short-TTL presigned GET (15 min, 01 §5.4) → local cache (`LocalFileStorageAdapter`); server jobs read objects directly (binding) |
| How does the UI preview? | cached blob + per-format renderer contracts (AD-10, artifacts page); unsupported formats = kept + downloadable, **no native preview claim** (ADR §16) |

## 3. Metadata ↔ object consistency (mission §21 last rule)

- `artifacts`/`documents` rows (Postgres, 01 §4.3/4.6) carry `r2_key`, `sha256`,
  `size_bytes`, `mime`, `status`; the object carries no business meaning.
- **Object without metadata** (orphan): reconcilable — a server job scans
  user-prefixed keys (`user_id` is in the key) and either links it to the creating
  job/row or marks it `orphan` for GC (retention = wave-0 data; V1 default: keep +
  flag, no auto-delete without a documented policy).
- **Metadata without object** (deleted/failed): `status = 'missing'` → UI shows
  "source unavailable" (state, 01 §6) + re-generate/re-download action; the row stays
  (historical integrity, provenance AD-11).

## 4. Lifecycle & retention

- No public bucket (ever, AD-16); versioning: **not used in V1** (re-evaluate if
  artifact versioning is required — marked NEEDS_DECISION in the feature catalog);
  deletion = module-owned (Artifact module deletes its objects; retention rules =
  wave-0 data, OQ-03); large-file cleanup follows the reconciler above.

## 5. Security

Private buckets + presigned URLs only (no public access, no R2 key on the device —
AD-3, 04 §7.2b test); per-user key prefix + server-side JWT check = ownership;
presigned TTLs short (15 min GET / 5 min PUT, 01 §5.4); secrets in Cloudflare
Secrets Store / Supabase Secrets (01 §5.6), owner Foundation (AD-16c).
